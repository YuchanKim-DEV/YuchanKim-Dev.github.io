- 문제 링크: 코드트리 정보에 따른 수 2
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_정보에따른수2.java`
- 난이도: Medium, 40XP (정답률 69%)
- 제한: 2 ≤ T ≤ 100, 1 ≤ a ≤ b ≤ 1000, 1 ≤ xᵢ ≤ 1000, xᵢ는 모두 다름, S와 N은 각각 최소 1개 (1초)

## 문제 설명

수직선 위에 글자 `S` 또는 `N`이 T개 놓여 있다. 정수 위치 `k`에서 가장 가까운 `S`까지의 거리를 `d1`, 가장 가까운 `N`까지의 거리를 `d2`라 할 때 `d1 <= d2`이면 **특별한 위치**다. `a <= k <= b` 중 특별한 위치의 개수를 구한다.

```
3 1 10
S 10
N 4
S 1     → 6   (k = 1, 2, 7, 8, 9, 10)
```

## 시행착오

이번에는 푸는 중에 힌트를 받지 않았다. 구조는 단순하다. **위치 `k`를 하나씩 정하고, 그 `k`에서 모든 글자를 훑어 `S`와 `N` 각각의 최단 거리를 구한 뒤 비교한다.**

- `d1`, `d2`를 `Integer.MAX_VALUE`로 시작하고, 글자 종류에 따라 거리의 최솟값만 갱신한다. S와 N이 각각 최소 1개 있다는 제한 덕에 `MAX_VALUE`가 비교에 남지 않는다.
- 조건은 `d1 <= d2`로 **같을 때도 특별한 위치**다. 등호를 빼면 예제의 `k = 7`(둘 다 거리 3)이 빠진다.
- `d1`, `d2`는 **위치마다 새로** 시작해야 한다. 안쪽 반복문 바깥, `k` 반복문 안에 둔다.

## 최종 코드

```java
int ans = 0;
for (int i = a; i <= b; i++) {
    int d1 = Integer.MAX_VALUE;
    int d2 = Integer.MAX_VALUE;
    for (int j = 0; j < c.length; j++) {
        if (c[j] == 'S') {
            d1 = Math.min(Math.abs(x[j] - i), d1);
        } else if (c[j] == 'N') {
            d2 = Math.min(Math.abs(x[j] - i), d2);
        }
    }
    if (d1 <= d2) {
        ans++;
    }
}
return ans;
```

## 추적표: 예제, k = 7 / k = 5

글자: S(10), N(4), S(1)

| k | d1 (S: 10, 1) | d2 (N: 4) | d1 <= d2 | 특별? |
|---|---|---|---|---|
| 7 | min(3, 6) = 3 | 3 | ✅ (같음) | ✅ |
| 5 | min(5, 4) = 4 | 1 | ❌ | ❌ |

특별한 위치는 1, 2, 7, 8, 9, 10으로 6개.

## 오늘 배운 내용

- "가장 가까운 ~까지의 거리"는 **종류별로 최솟값을 따로 들고 간다.** 한 번 훑으면서 종류에 따라 `d1`, `d2`를 각각 갱신한다.
- 최솟값 변수의 시작값은 `Integer.MAX_VALUE`. 이 값이 끝까지 남는 경우(해당 종류가 없을 때)는 제한 조건으로 막혀 있는지 확인한다.
- 위치마다 새로 계산하는 변수는 **그 위치의 반복문 안에서** 초기화한다.

## 오답노트

- 이번에는 틀린 곳이 없었다. 다만 제한 조건 "S와 N이 각각 최소 1개"가 `MAX_VALUE` 비교를 안전하게 만든다는 점은 기억해 둔다.
- "같으면 특별하다"는 등호 처리는 예제의 `k = 7`로 바로 확인할 수 있다.

## AI라면 어떻게 풀었을까

구조는 같다. 범위가 아주 크다면 S와 N의 위치를 각각 정렬해 두고 `k`마다 **이분 탐색**으로 가장 가까운 글자를 찾는다. 이 문제는 `b <= 1000`, `T <= 100`이라 위치 × 글자 = 10만 번이면 충분해서 지금 방식이 맞다.
