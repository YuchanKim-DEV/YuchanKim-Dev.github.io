## 문제 설명

논문별 인용 횟수 배열 `citations`가 주어진다. **"h번 이상 인용된 논문이 h편 이상"**이 되는 h 중 최댓값(H-Index)을 구한다.

```
citations = [3, 0, 6, 1, 5] → 3
```

3번 이상 인용된 논문은 3, 6, 5로 3편이다(3 ≥ 3). 4번 이상은 6, 5로 2편뿐이라(2 < 4) 4는 안 된다.

## 시행착오

### 0차: 문제 정의를 잘못 읽음

처음 든 생각은 "1번 이상 인용된 논문은 4편이니까 이게 더 큰 거 아니야?"였다. **답을 "편수"로 착각했다.** h = 1에서 4편이 나온 건 "h = 1이 조건을 통과한다"는 뜻일 뿐이고, 답 후보는 4가 아니라 1이다.

"레벨 h 도전"으로 바꿔 생각하니 풀렸다. 레벨 h는 **"h번 이상 인용된 논문을 h편 내놔라"**이고, 숫자 h가 두 군데에 같이 쓰인다. 깬 레벨 중 가장 높은 레벨이 답이다. 레벨 1에서 4편을 낸 건 레벨 1을 여유 있게 깬 것이지 레벨 4를 깬 게 아니다.

### 1차: 출력 `2 0 0 0 0 0 0 0 0 0`

```java
for (int i = 0; i < max; i++) {             // ③ 최대 인용수 자체는 도전 안 함
    int count = 0;
    for (int j = 0; j < citations.length; j++) {
        if (i >= citations[j]) {            // ① i번 "이하" 인용된 논문을 셈
            count++;
        }
    }
    if (count == i) {                       // ② 편수가 h와 "딱 같을" 때만 통과
        answer = i;
        break;                              // ② 처음 통과한 레벨에서 멈춤
    }
}
```

h를 하나씩 올리면서 매번 개수를 세는 큰 틀(레벨 도전)은 맞았다. 틀린 곳은 세 군데였다.

1. **비교 방향**: 레벨 i에서 세야 하는 건 i번 **이상** 인용된 논문이다. `citations[j] >= i`(= `i <= citations[j]`)여야 한다.
2. **`break`**: 레벨 0은 항상 통과하니 대부분 0에서 멈췄다. 원하는 건 처음이 아니라 **마지막으로** 통과한 레벨이다.
3. **`i < max`**: `[4, 4, 4, 4]`는 max = 4인데 레벨 4를 도전조차 못 한다. 답이 바로 4다.

### 2차: 3개 틀림 (`[1, 1, 1]`, `[1, 4]`, `[0, 1, 2, 3, 4, 5, 6]`)

①·③을 고치고 `break`를 지웠는데 `count == i`는 그대로였다. `[1, 1, 1]`의 레벨 1은 `count = 3`, `i = 1`이라 `3 == 1`이 거짓이 되어 통과로 안 잡혔다. 조건은 "h편 **이상**"이니 `count >= i`로 고쳐 10개 모두 통과했다.

## 최종 코드

```java
public int solution(int[] citations) {
    int answer = 0;
    Arrays.sort(citations);
    int max = 0;
    for (int i = 0; i < citations.length; i++) {
        max = Math.max(citations[i], max);
    }

    for (int i = 0; i <= max; i++) {                 // 레벨 0 ~ 최대 인용수
        int count = 0;
        for (int j = 0; j < citations.length; j++) {
            if (i <= citations[j]) {                 // i번 이상 인용된 논문
                count++;
            }
        }
        if (count >= i) {                            // h편 이상이면 통과
            answer = i;                              // 마지막으로 통과한 레벨이 남는다
        }
    }
    return answer;
}
```

테스트 10개가 통과했고, 랜덤 30,000건에서 아래 AI 풀이와 결과가 같았다. 최악 입력(1,000편 × 10,000회 인용)도 6ms였다.

## 추적표: `[3, 0, 6, 1, 5]`

| 레벨 h | h번 이상 인용된 논문 | 편수 | 편수 ≥ h | answer |
|---|---|---|---|---|
| 0 | 0, 1, 3, 5, 6 | 5 | ✓ | 0 |
| 1 | 1, 3, 5, 6 | 4 | ✓ | 1 |
| 2 | 3, 5, 6 | 3 | ✓ | 2 |
| 3 | 3, 5, 6 | 3 | ✓ | **3** |
| 4 | 5, 6 | 2 | ✗ | 3 |
| 5 | 5, 6 | 2 | ✗ | 3 |
| 6 | 6 | 1 | ✗ | 3 |

h가 커질수록 편수는 줄고 h는 늘어난다. 한 번 ✗가 되면 다시 ✓로 돌아오지 않는다.

## 오늘 배운 내용

**정의에 숫자가 두 번 나오면 무엇을 답으로 내는지부터 확인한다.** H-Index는 "h번 이상 인용된 논문이 h편 이상"에서 **h**를 묻는다. 편수는 h가 통과했는지 판단하는 재료일 뿐이다. "레벨 h를 깨려면 조건 X"로 바꿔 쓰면 답(레벨)과 판단 재료(편수)가 섞이지 않는다.

## 오답노트

- **틀렸던 지점 1**: 답을 편수(4)로 착각. **왜**: "h번 이상 인용된 논문 수"를 세다 보니 센 값이 답처럼 보였다. **다음에**: 문제에서 "~의 최댓값"이 **무엇의** 최댓값인지 밑줄 긋는다.
- **틀렸던 지점 2**: `i >= citations[j]`(방향 반대). **왜**: "i와 citations 비교"까지만 생각하고 어느 쪽이 커야 하는지 문장으로 안 읽었다. **다음에**: 조건을 한국어로 읽어 본다. "인용수가 i 이상" → `citations[j] >= i`.
- **틀렸던 지점 3**: `break`. **왜**: "찾으면 멈춘다"는 습관. 작은 레벨부터 올라가면 처음 통과하는 건 최솟값이다. **다음에**: 최댓값을 찾을 때 작은 쪽부터 돈다면 멈추지 말고 갱신만 한다(또는 큰 쪽부터 돌고 처음에 멈춘다).
- **틀렸던 지점 4**: `count == i`. **왜**: "h편 **이상**"의 "이상"을 놓쳤다. **다음에**: 문제의 이상/이하/초과/미만을 `>=`, `<=`, `>`, `<`로 그대로 옮긴다.
- **틀렸던 지점 5**: `i < max`. **왜**: 반복문 끝을 습관적으로 `<`로 썼다. **다음에**: 범위 끝값(여기선 max) 자체가 답이 될 수 있는지 테스트 하나로 확인한다.

## 꿀팁

**정렬된 배열에서 "x 이상인 원소 개수"는 인덱스로 바로 나온다.** 오름차순 정렬 후 인덱스 `i`부터 끝까지는 `n - i`개이고, 모두 `arr[i]` 이상이다. 그래서 개수를 세는 안쪽 반복문 없이 `n - i`로 대신할 수 있다. 이번 풀이에 `Arrays.sort`를 넣었지만 실제로는 안 쓰고 있었는데, 정렬의 효과는 이렇게 써야 나온다.

## AI라면 어떻게 풀었을까

**정렬을 개수 세기에 직접 쓴다.** 오름차순 정렬 후 인덱스 `i`부터 끝까지 `n - i`편은 전부 `citations[i]` 이상 인용됐다. 그래서 `citations[i] >= n - i`면 "n - i번 이상 인용된 논문이 n - i편"이 바로 성립한다. 앞(작은 값)에서부터 보면 `n - i`가 큰 쪽부터 확인되므로, 처음 성립하는 `n - i`가 최댓값이다.

```java
public int solutionAlt(int[] citations) {
    Arrays.sort(citations);
    int n = citations.length;
    for (int i = 0; i < n; i++) {
        int h = n - i;                  // 인덱스 i부터 끝까지의 논문 수
        if (citations[i] >= h) {
            return h;
        }
    }
    return 0;
}
```

트레이드오프: 레벨마다 배열 전체를 다시 세는 이중 for(`O(최대 인용수 × n)`)가 정렬 + 한 바퀴(`O(n log n)`)로 줄어든다. 대신 "왜 처음 성립하는 게 최댓값인지"를 이해해야 해서 처음 보면 덜 직관적이다. 이 문제는 n ≤ 1,000이라 본인 풀이도 충분히 빠르다.
