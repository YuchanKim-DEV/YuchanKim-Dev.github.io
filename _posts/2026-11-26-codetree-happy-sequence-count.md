- 문제 링크: 코드트리 행복한 수열의 개수
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_행복한수열의개수.java`
- 난이도: Easy, 60XP (정답률 40%, 평균 72분)
- 제한: 1 ≤ M ≤ N ≤ 100, 격자 값 1~100, Time Limit 1000ms

## 문제 설명

N × N 격자가 주어진다. **같은 숫자가 연속으로 M개 이상 나오는 구간**이 있는 수열을 "행복한 수열"이라 한다. 각 행(N개)과 각 열(N개), 총 2N개의 수열 중 행복한 수열의 개수를 구한다.

```
3 2
1 2 2      → 2   (첫 행 "1 2 2", 첫 열 "1 1 1"만 행복)
1 3 4
1 2 3
```

## 시행착오

로직 구조(줄마다 `prev`, `count`로 연속 개수 세기)는 처음부터 맞았다. 틀린 건 **`count`의 초기값과 검사 위치**였고, 네 번 고쳤다.

1. **`count` 초기값 0 → 1.** `prev = grid[i][0]`으로 첫 칸을 이미 읽었으니 연속 길이는 이미 1이다. 0으로 두면 M개 이상이 아니라 M+1개 이상이어야 통과하고, `count = 0`으로 리셋하는 줄도 같이 틀렸다. 값이 바뀔 때는 `count = 1`이다.
2. **`count >= m` 검사가 `prev == grid` 안에만 있었다.** `count++`가 일어나는 곳에서만 검사해서, M = 1이고 `1 2 3`처럼 같은 값이 한 번도 안 이어지는 줄은 영영 검사가 안 됐다. 검사를 `if/else if` 바깥, `j` 반복문 안으로 옮겼다.
3. **검사를 `j` 반복문 밖으로 옮긴 것은 오답이었다.** N = 1일 때 `j` 반복이 안 도는 문제를 고치려고 밖으로 뺐더니 두 가지가 깨졌다.
   - 줄 끝의 `count`는 "마지막으로 이어진 구간의 길이"라서, `1 1 2`(M = 2)처럼 중간에 있던 구간을 놓친다.
   - `break`가 `j`가 아니라 `i` 반복문을 빠져나가서, 행에서 최대 1개, 열에서 최대 1개만 센다.
4. **그래서 `j` 반복문 안으로 되돌리고, N = 1은 따로 처리했다.** `j`가 1부터 도니까 N = 1이면 한 번도 안 돌아 0이 나온다. 이때는 M도 1이고, 행 1개 + 열 1개 = 정답 2다.

## 최종 코드

```java
if (n == 1) {
    System.out.print(2);
} else {
    // grid 입력 ...
    int ans = 0;
    for (int i = 0; i < n; i++) {            // 행
        int prev = grid[i][0];
        int count = 1;
        for (int j = 1; j < n; j++) {
            if (prev == grid[i][j]) {
                count++;
            } else {
                count = 1;
                prev = grid[i][j];
            }
            if (count >= m) {                // 바뀔 때마다 검사
                ans++;
                break;                       // 이 줄은 확정, 이 줄만 빠져나간다
            }
        }
    }
    // 열은 grid[j][i]로 같은 코드를 한 번 더
    System.out.print(ans);
}
```

## 추적표: 예제 1의 첫 행 `1 2 2` (M = 2)

| j | grid[0][j] | prev와 비교 | count | `count >= 2` |
|---|---|---|---|---|
| (시작) | 1 | | 1 (prev = 1) | |
| 1 | 2 | 다름 → count = 1, prev = 2 | 1 | ❌ |
| 2 | 2 | 같음 → count++ | 2 | ✅ ans++, break |

만약 3번 실수처럼 검사를 `j` 반복 밖에 두면, 줄이 `1 1 2`일 때 끝에서 `count`가 다시 1이 되어 구간을 놓친다.

## 오늘 배운 내용

- **연속 개수는 1에서 시작한다.** 첫 칸을 읽는 순간 이미 길이 1이다. 0으로 시작하면 한 칸씩 어긋난다.
- **검사는 값이 바뀔 때마다(매 칸마다) 한다.** 반복문이 끝난 뒤의 `count`는 "마지막 구간"이라서, 최대 길이를 보려면 계속 검사하거나 최댓값을 따로 갱신해야 한다.
- `break`는 **자기가 속한 가장 안쪽 반복문만** 빠져나간다. 반복문 밖으로 옮기면 바깥 반복문을 끝내 버릴 수 있다.
- 경계 입력(N = 1)은 "반복문이 한 번도 안 도는 경우"를 따라가 보면 찾을 수 있다.

## 오답노트

- `count = 0`으로 시작 → `1`.
- 검사가 `==` 분기 안에만 있음 → M = 1일 때 실패.
- 검사를 `j` 반복문 밖으로 옮김 → 중간 구간 누락 + `break`가 바깥 반복을 끝냄.
- N = 1에서 `j` 반복이 안 돎 → 정답 2를 따로 처리.
- 4번 중 3번째는 N = 1을 고치려다 정상이던 코드를 깨뜨린 수정이었다. **고친 뒤에는 이전에 통과하던 경우(M = 1, 중간 구간)를 다시 따라가 봐야 한다.**

## AI라면 어떻게 풀었을까

행 검사와 열 검사가 복붙이라서, "수열 하나가 행복한가"를 메서드로 빼고 열은 배열로 꺼내 넘긴다.

```java
static boolean happy(int[] a, int m) {
    int run = 1;
    if (run >= m) return true;                    // M = 1 (N = 1도 여기서 처리)
    for (int i = 1; i < a.length; i++) {
        run = (a[i] == a[i - 1]) ? run + 1 : 1;
        if (run >= m) return true;
    }
    return false;
}

int ans = 0;
for (int i = 0; i < n; i++) {
    int[] col = new int[n];
    for (int j = 0; j < n; j++) col[j] = grid[j][i];
    if (happy(grid[i], m)) ans++;                 // i번째 행
    if (happy(col, m)) ans++;                     // i번째 열
}
```

핵심은 같다. `run`을 1로 시작하고, 값이 바뀔 때마다 검사한다. 반복문 전에 `run >= m`을 한 번 검사하면 N = 1을 따로 `if (n == 1)`로 빼지 않아도 된다.
