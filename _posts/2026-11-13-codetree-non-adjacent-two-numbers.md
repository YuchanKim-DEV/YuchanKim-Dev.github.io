- 문제 링크: 코드트리 Trail 2. Novice Mid > Chapter 6 > Lesson 1 (자리 수 단위로 완전탐색)
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_인접하지않은2개의수.java`
- 난이도: 10XP (정답률 71%)

## 문제 설명

정수 N개 중 **인덱스 차이가 2 이상**인 두 수를 골라 합의 최댓값을 구한다.

```
6
2 1 6 2 7 8   → 14   (6 + 8. 7과 8은 인접해서 같이 못 고름)
```

## 시행착오

두 수를 고르는 모든 쌍을 보되, 인접한 쌍을 건너뛰면 된다. 헷갈릴 만한 곳은 반복문 범위뿐이었다.

- 바깥 `i`는 `0 ~ n-3`. 뒤에 `i + 2`가 있어야 하므로 `i < n - 2`.
- 안쪽 `j`는 `i + 2`부터 시작. 이렇게 하면 `i`와 인접한 `i+1`이 자연스럽게 빠지고, `(i, j)`와 `(j, i)`가 중복되지도 않는다.
- 최댓값 시작값은 `0`이 아니라 `Integer.MIN_VALUE`. 음수만 있어도 맞게 나온다.

## 최종 코드

```java
int max = Integer.MIN_VALUE;
for (int i = 0; i < arr.length - 2; i++) {
    for (int j = i + 2; j < arr.length; j++) {
        max = Math.max(max, arr[j] + arr[i]);
    }
}
```

## 추적표: 예제

| i | j 범위 | 이 줄의 최댓값 |
|---|---|---|
| 0 (2) | 2~5 | 2+8 = 10 |
| 1 (1) | 3~5 | 1+8 = 9 |
| 2 (6) | 4~5 | 6+8 = 14 |
| 3 (2) | 5 | 2+8 = 10 |

전체 최댓값 14.

## 오늘 배운 내용

- 쌍 문제는 `j`를 `i`보다 뒤에서 시작하면 **중복이 없어진다.** 거기에 "인접 제외"는 시작값을 `i + 2`로 바꾸는 것으로 끝난다.
- 합·곱의 최댓값은 시작값을 `MIN_VALUE`로 둔다.

## 오답노트

- 이번에는 틀린 곳이 없었다. 반복문 범위를 `3개짜리 [1,100,3]`으로 손으로 돌려 보면 (0,2) 하나만 나오는 것을 확인할 수 있다.

## AI라면 어떻게 풀었을까

반복문 하나로 줄인다. `j`번째 수의 짝이 될 수 있는 것은 `0 ~ j-2`번째이므로, 그 구간의 최댓값만 들고 간다.

```java
int best = Integer.MIN_VALUE;
int prefixMax = arr[0];
for (int j = 2; j < arr.length; j++) {
    best = Math.max(best, prefixMax + arr[j]);
    prefixMax = Math.max(prefixMax, arr[j - 1]);   // 다음 j를 위해 j-1을 편입
}
```

O(N²) → O(N). 이 문제는 N이 작아 이중 반복문으로 충분하다.
