## 문제 설명

정수 배열을 **2진수로 나타냈을 때 1의 개수가 적은 순서**로 정렬한다. 개수가 같으면 **값이 작은 순서**다. 값은 0 ~ 10,000이다.

```
[0,1,2,3,4,5,6,7,8]                  → [0,1,2,4,8,3,5,6,7]
[1024,512,256,128,64,32,16,8,4,2,1]  → [1,2,4,8,16,32,64,128,256,512,1024]
```

Comparator 드릴 세 번째 문제다. 바로 전에 푼 [특이한 정렬]({% post_url 2026-10-24-special-sort-programmers-lv0 %})과 같은 모양이고, 새로운 건 1의 개수를 구하는 `Integer.bitCount(x)` 하나뿐이었다(5 = `101` → 2).

## 시행착오

**없었다.** 시작부터 9분 만에 7개 테스트를 한 번에 통과했다.

특이한 정렬 코드에서 바뀐 곳은 두 군데뿐이다.

| | 특이한 정렬 | LC1356 |
|---|---|---|
| map에 넣는 값 | `Math.abs(n - x)` | `Integer.bitCount(x)` |
| 2기준 | `b - a` (큰 게 앞) | `a - b` (작은 게 앞) |

최근 정렬 문제마다 막혔던 "`?`/`:` 한쪽에 값 하나만 반환" 실수가 이번에도 나오지 않았다. 드릴 두 문제 연속이다.

한 가지 짚을 점이 있다. 방금 특이한 정렬에서 배운 `Integer !=` 함정이 이번 코드에도 그대로 있다.

```java
map.get(a) != map.get(b)
```

이 문제는 1의 개수가 최대 14(10,000 이하)라 -128 ~ 127 캐시 안에 있어서 **우연히 맞는다.** 값 범위가 다른 문제에서 이 습관이 나오면 또 제출에서 틀린다.

## 최종 코드

```java
public int[] sortByBits(int[] arr) {
    Integer[] temp = new Integer[arr.length];
    HashMap<Integer, Integer> map = new HashMap<>();

    for (int i = 0; i < arr.length; i++) {
        temp[i] = arr[i];
        map.put(arr[i], Integer.bitCount(arr[i]));     // 숫자 → 1의 개수
    }

    Arrays.sort(temp, (a, b) -> map.get(a) != map.get(b)
            ? map.get(a) - map.get(b)     // 1의 개수가 다르면: 적은 게 앞
            : a - b);                     // 같으면: 작은 수가 앞

    for (int i = 0; i < temp.length; i++) {
        arr[i] = temp[i];
    }
    return arr;
}
```

랜덤 20,000건에서 아래 AI 풀이와 결과가 같았다.

## 추적표: `[0,1,2,3,4,5,6,7,8]`

| 값 | 2진수 | 1의 개수 |
|---|---|---|
| 0 | `0` | 0 |
| 1, 2, 4, 8 | `1`, `10`, `100`, `1000` | 1 |
| 3, 5, 6 | `11`, `101`, `110` | 2 |
| 7 | `111` | 3 |

1의 개수로 묶고, 묶음 안은 값 오름차순 → `[0, 1, 2, 4, 8, 3, 5, 6, 7]`

## 오늘 배운 내용

**2기준 정렬은 틀이 하나다.** `(a, b) -> 1기준이 다르면 ? 1기준 비교 : 2기준 비교`에서 바뀌는 건 "1기준이 무엇인지"(빈도, 거리, 1의 개수)와 "2기준 방향"(`a - b`, `b - a`)뿐이다. 틀을 손에 익히니 새 문제에서도 기준만 갈아 끼우면 됐다.

## 오답노트

- **주의할 지점**: `map.get(a) != map.get(b)`(통과했지만 위험). **왜**: 직전 문제에서 `.equals`로 고쳤는데, 새 파일에서는 익숙한 `!=`가 다시 나왔다. **다음에**: `map.get(...)`끼리 비교하는 줄을 쓰면 `.equals`인지 한 번 본다. 아니면 아래처럼 map 없이 `int`로 계산해 비교한다.

## AI라면 어떻게 풀었을까

**1의 개수를 저장하지 않고 Comparator 안에서 바로 계산한다.** `Integer.bitCount(x)`는 언제든 다시 구할 수 있어서 `HashMap`이 필요 없다. `comparing` → `thenComparing`으로 잇으면 `Integer !=` 비교 자체가 사라진다.

```java
public int[] sortByBitsAlt(int[] arr) {
    Integer[] temp = new Integer[arr.length];
    for (int i = 0; i < arr.length; i++) {
        temp[i] = arr[i];
    }
    Arrays.sort(temp, Comparator.comparing((Integer x) -> Integer.bitCount(x))   // 1의 개수 오름차순
            .thenComparing(Comparator.naturalOrder()));                         // 같으면 값 오름차순
    for (int i = 0; i < arr.length; i++) {
        arr[i] = temp[i];
    }
    return arr;
}
```

트레이드오프: 코드가 짧고 범위가 커져도 안전하다. 대신 비교할 때마다 `bitCount`를 다시 계산한다. `bitCount`는 CPU 명령 하나 수준이라 이 문제에서는 차이가 없다.
