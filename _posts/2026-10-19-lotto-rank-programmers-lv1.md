## 문제 설명

로또 번호 6개(`lottos`) 중 일부가 낙서로 지워져 `0`으로 표시된다. 당첨 번호(`win_nums`)가 주어질 때, 지워진 번호가 **전부 맞았다면**(최고 순위)과 **전부 틀렸다면**(최저 순위)을 차례로 반환한다. 6개 일치 1등, 5개 2등, 4개 3등, 3개 4등, 2개 5등, 그 외는 6등(낙첨)이다.

```
lottos = [44,1,0,0,31,25], win_nums = [31,10,45,1,6,19] → [3, 5]
```

## 시행착오

주말 이틀을 쉬고 돌아온 월요일 첫 문제(구현 슬롯, 워밍업)였다. Lv1인데도 "개어렵다"는 말이 먼저 나왔다. 문제가 길어서 어려워 보였을 뿐, 실제로 구할 것은 **두 개의 수**였다.

| 구할 것 | 예시 값 | 방법 |
|---|---|---|
| 0의 개수 | 2 | `lottos`에서 0을 센다 |
| 확실히 맞은 개수 | 2 (1, 31) | 0이 아닌 번호 중 당첨 번호에 있는 것 |

- 최고 순위: 맞은 개수 = 확실히 맞은 개수 + 0의 개수 = 4 → 3등
- 최저 순위: 맞은 개수 = 확실히 맞은 개수 = 2 → 5등

또 "이진 탐색을 하나도 안 썼다"고 했는데, 이 문제는 **구현** 문제라 이진 탐색이 필요 없다. 그날 이진 탐색은 두 번째 문제(LC33)였다.

### 1차: 개수는 맞게 셌지만 순위 변환이 1씩 작음

```java
answer[0] = 6 - correctNum - zeroNum;
answer[1] = 6 - zeroNum;
```

순위표는 `순위 = 7 - 맞은 개수`인데 `6 - 맞은 개수`로 써서 모든 값이 1씩 작았다. 게다가 최저 순위에 `correctNum`이 아니라 `zeroNum`을 썼다.

### 2차: 변환은 7로 고쳤지만 두 군데가 남음

```java
answer[1] = 7 - zeroNum;               // 최저 순위는 correctNum으로 계산해야 함
if (answer[0] > 6) { answer[0] = 1; }  // 6보다 크면 6등(낙첨)이어야 하는데 1등으로 바꿈
```

1. **최저 순위는 "0이 전부 틀렸다"고 볼 때**라 맞은 개수는 `correctNum`뿐이다. 예시 1이 통과한 건 `correctNum`과 `zeroNum`이 둘 다 2라서 우연히 같은 값이 나왔기 때문이다.
2. **맞은 개수가 0개면 `7 - 0 = 7`인데 답은 6등이다.** 이걸 `1`로 바꿔서 낙첨이 1등이 되었다.

## 최종 코드

```java
public int[] solution(int[] lottos, int[] win_nums) {
    int[] answer = new int[2];

    int zeroNum = 0;
    for (int i = 0; i < lottos.length; i++) {
        if (lottos[i] == 0) {
            zeroNum++;
        }
    }

    if (zeroNum == 6) {
        answer[0] = 1;
        answer[1] = 6;
        return answer;
    }

    int correctNum = 0;
    for (int i = 0; i < lottos.length; i++) {
        for (int j = 0; j < win_nums.length; j++) {
            if (lottos[i] == win_nums[j]) {
                correctNum++;
            }
        }
    }

    answer[0] = 7 - correctNum - zeroNum;   // 최고: 0이 전부 맞음
    answer[1] = 7 - correctNum;             // 최저: 0이 전부 틀림

    if (answer[0] > 6) {
        answer[0] = 6;                      // 맞은 개수 0개 → 6등
    }
    if (answer[1] > 6) {
        answer[1] = 6;
    }
    return answer;
}
```

8개 테스트가 모두 통과했고, 랜덤 50,000건에서도 정답과 일치했다. (맨 위의 `zeroNum == 6` 분기는 아래 공식으로도 `[1, 6]`이 나오므로 없어도 된다.)

## 추적표: 순위 변환

| 맞은 개수 | 7 - 개수 | 보정 후 순위 |
|---|---|---|
| 6 | 1 | 1 |
| 5 | 2 | 2 |
| 4 | 3 | 3 |
| 3 | 4 | 4 |
| 2 | 5 | 5 |
| 1 | 6 | 6 |
| 0 | **7** | **6** (낙첨) |

## 오늘 배운 내용

**문제가 길어 보여도 "구해야 하는 수"를 먼저 표로 적으면 짧아진다.** 이 문제는 "0의 개수"와 "확실히 맞은 개수" 두 개가 전부였고, 나머지는 그 둘을 더하거나 빼서 순위로 바꾸는 일이었다.

**공식으로 변환할 때는 경계값(0개, 6개)을 꼭 대입해 본다.** `7 - 개수`는 0개일 때 7이 나와서 보정이 필요했다.

## 오답노트

- **틀렸던 지점 1**: `6 - 개수`로 변환. **왜**: 순위표를 손으로 한 번도 대입하지 않았다. **다음에**: 공식을 쓰면 6개(→1등)와 0개(→6등)를 넣어 확인한다.
- **틀렸던 지점 2**: 최저 순위에 `zeroNum`을 씀. **왜**: 두 변수 이름이 비슷해서 헷갈렸고, 예시 1에서 우연히 맞아 넘어갔다. **다음에**: 두 값이 같은 예시만 보지 말고 값이 다른 테스트로 확인한다.
- **틀렸던 지점 3**: 7을 `1`로 보정. **왜**: "6보다 크면 바꾼다"까지는 맞았는데 "무엇으로"를 순위표에서 확인하지 않았다. **다음에**: 보정값은 표에서 읽는다(0개 → 6등).
- **좋았던 점**: 0의 개수와 맞은 개수를 세는 두 반복문은 처음부터 정확했다.

## AI라면 어떻게 풀었을까

`7 - 개수` + `if` 보정 대신 **순위표를 배열로** 만들어 둔다. `rank[맞은 개수]`가 곧 순위라서 0개·1개가 6등이 되는 예외를 따로 처리할 필요가 없다. 또 당첨 번호를 `HashSet`에 넣으면 이중 `for` 없이 `contains`로 바로 확인한다.

```java
public int[] solutionAlt(int[] lottos, int[] win_nums) {
    int[] rank = { 6, 6, 5, 4, 3, 2, 1 };          // rank[맞은 개수] = 순위
    Set<Integer> win = new HashSet<>();
    for (int w : win_nums) {
        win.add(w);
    }
    int zero = 0, hit = 0;
    for (int n : lottos) {
        if (n == 0) {
            zero++;                                 // 알아볼 수 없는 번호
        } else if (win.contains(n)) {
            hit++;                                  // 확실히 맞은 번호
        }
    }
    return new int[] { rank[hit + zero], rank[hit] };   // 최고, 최저
}
```

트레이드오프: 순위표를 눈으로 보고 그대로 배열에 옮기므로 경계값 실수가 생길 수 없고, `zeroNum == 6` 같은 특수 분기도 필요 없다. 대신 배열 인덱스가 "맞은 개수"라는 약속을 알아야 읽힌다. 이 문제는 길이가 6이라 이중 `for`도 충분히 빠르다. 랜덤 50,000건에서 본인 풀이와 출력이 일치했다.
