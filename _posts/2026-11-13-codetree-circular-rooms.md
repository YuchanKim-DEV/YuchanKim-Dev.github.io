## 문제 설명

방 N개가 원으로 놓여 있고 번호가 커지는 방향으로만 이동한다(N번 다음은 1번). 각 방에 들어가야 하는 인원이 주어지고 모두 같은 방에서 출발한다. 출발 방을 잘 골랐을 때 **(인원 × 이동 거리)의 합**의 최솟값을 구한다.

```
5
4 7 8 6 4   → 48   (2번 방에서 시작: 0 + 8×1 + 6×2 + 4×3 + 4×4)
```

## 시행착오

출발 방을 하나씩 정하고(바깥 루프), 그때의 거리 합을 구한다(안쪽 루프). 핵심은 한 가지, 출발 `i`에서 도착 `j`까지의 **반시계 거리**다.

- `j >= i`: `j - i`
- `j < i`: 한 바퀴를 돌아 `j - i + N`

이 둘을 한 식으로 쓰면 `(j - i + N) % N`이다. `+ N`을 먼저 해야 하는 이유는 Java의 `%`가 음수 피연산자에 음수 결과를 내기 때문이다.

## 최종 코드

```java
int min = Integer.MAX_VALUE;
for (int i = 0; i < N; i++) {
    int total = 0;
    for (int j = 0; j < N; j++) {
        total += arr[j] * ((j - i + N) % N);
    }
    min = Math.min(min, total);
}
```

## 추적표: 예제 `[4,7,8,6,4]`, 출발 i = 1

| j | arr[j] | (j-1+5)%5 | 기여 |
|---|---|---|---|
| 0 | 4 | 4 | 16 |
| 1 | 7 | 0 | 0 |
| 2 | 8 | 1 | 8 |
| 3 | 6 | 2 | 12 |
| 4 | 4 | 3 | 12 |

합 48. 다른 출발 방은 이보다 크다.

## 오늘 배운 내용

- 원형 문제의 기본형: **`(도착 - 출발 + N) % N`**.
- 완전탐색은 "무엇을 하나 정한다(출발 방)" + "그 상태로 전부 계산한다"의 두 겹 반복문.

## 오답노트

- 이번에는 틀린 곳이 없었다. `(j - i) % N`으로 쓰면 `j < i`일 때 음수가 나온다는 점만 기억해 둔다.
- 인원 × 거리가 커지는 제한이면 `int`가 넘칠 수 있으니 `long`을 검토한다.

## AI라면 어떻게 풀었을까

출발 방을 `i`에서 `i + 1`로 옮길 때 합이 어떻게 변하는지로 O(N)에 푼다.

```
새 합 = 이전 합 - (전체 인원 - arr[i]) + arr[i] × (N - 1)
```

`i`번을 뺀 모두의 거리가 1씩 줄고, 맨 뒤로 가는 `i`번의 사람만 `N - 1`칸이 된다. N이 작으면 위 이중 반복문으로 충분하다.
