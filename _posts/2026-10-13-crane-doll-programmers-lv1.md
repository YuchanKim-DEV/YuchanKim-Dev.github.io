## 문제 설명

N x N 격자(`board`)에 인형이 쌓여 있고(0은 빈칸), 크레인이 `moves`의 **열 번호**(1부터)에서 그 열의 **맨 위 인형**을 집어 바구니에 쌓는다. 바구니에서 같은 인형 두 개가 **연속**으로 쌓이면 터져서 사라진다. 사라진 인형의 개수를 구한다. 빈 열에서 크레인을 작동하면 아무 일도 일어나지 않는다.

```
board = [[0,0,0,0,0],[0,0,1,0,3],[0,2,5,0,1],[4,2,4,4,2],[3,5,1,3,1]]
moves = [1,5,3,5,1,2,1,4]   → 4
```

## 시행착오

### 0차: 풀기 전에 문제부터 다시 읽기

코드를 짜기 전에 첫 번째 의문이 나왔다. **"2차원 배열인데 `moves`가 왜 좌표 하나뿐이지? `[1,4]` 같은 좌표가 아닌가?"**

답은 `moves`의 값이 **열 번호**라는 것이었다. 크레인은 **좌우로만** 움직이고, 열을 정하면 그 열을 위에서 아래로 내려가 **처음 만나는 0이 아닌 칸**을 집는다. 그래서 **행은 입력이 아니라 내가 찾아야 하는 값**이다. 또 열은 1부터인데 배열 인덱스는 0부터라서 `moves[i] - 1`이 필요했다. "문제도 잘 읽어야겠다"는 말이 이날의 소감이었다.

### 1차: `moves[i].length`

```java
for (int j = 0; j < moves[i].length; j++) { ... }
// error: int cannot be dereferenced
```

`board`는 2차원(`int[][]`)이라 `board[i].length`가 되지만, `moves`는 **1차원**(`int[]`)이라 `moves[i]`가 숫자 하나다. 숫자에는 `.length`가 없다. 직전에 `board[0].length`(열 개수)를 배웠는데 그걸 `moves`에 붙였다.

### 2차: 모두 0 — 행과 열이 뒤바뀜, 집은 칸을 지우지 않음

```java
for (int j = 0; j < board[moves[i] - 1].length; j++) {
    int num = board[moves[i] - 1][j];     // [행][열] 자리에 [열][j]를 넣음
    ...
}
```

`board[행][열]` 순서인데 `moves[i] - 1`(열 번호)을 **행 자리**에 넣고 `j`를 **열 자리**에 넣었다. 그러면 "열을 위에서 아래로 내려가는" 게 아니라 "행 하나를 왼쪽에서 오른쪽으로 훑는" 반복이 된다. 거기에 **집은 칸을 `0`으로 바꾸는 줄이 없어서** 같은 열을 다시 누르면 같은 인형을 또 집었다.

### 3차: 반복의 끝값 `board[j].length`

```java
for (int j = 0; j < board[j].length; j++) {   // ArrayIndexOutOfBoundsException: Index 5
```

`j`가 반복 조건 안에 들어가 있다. 열이 비어서 끝까지 내려가면 `j`가 5가 되고, 조건을 검사하려고 `board[5]`를 읽다가 터졌다. 반복의 끝값은 `j`가 변해도 안 변하는 값이어야 한다. 행을 세는 반복이니 **행 개수 `board.length`**였다. (정사각형이라 `board[0].length`와 값은 같지만, 의미가 다르다.)

### 4차: 터진 개수를 1씩 셈

```java
stack.pop();
answer++;     // 한 번 pop = 인형 2개가 사라짐
```

문제가 묻는 건 "터진 **인형의 개수**"다. 같은 인형 **두 개**가 터지므로 `pop` 한 번에 **2**개다. 그래서 모든 결과가 정확히 절반으로 나왔다. `answer += 2`로 고쳤다.

## 최종 코드

```java
public int solution(int[][] board, int[] moves) {
    Stack<Integer> stack = new Stack<>();            // 바구니
    int answer = 0;

    for (int i = 0; i < moves.length; i++) {         // 이동을 하나씩
        for (int j = 0; j < board.length; j++) {     // 그 열을 위(행 0)에서 아래로
            int num = board[j][moves[i] - 1];        // [행][열] — 열 번호는 1부터라 -1
            if (num != 0) {
                if (!stack.isEmpty() && stack.peek() == num) {
                    stack.pop();
                    answer += 2;                     // 두 개가 터짐
                } else {
                    stack.push(num);
                }
                board[j][moves[i] - 1] = 0;          // 집은 칸은 빈칸으로
                break;                               // 맨 위 하나만 집는다
            }
        }
    }
    return answer;
}
```

6개 테스트가 모두 통과했고, 랜덤 20,000건에서도 정답 시뮬레이션과 일치했다.

## 추적표: 예시의 앞부분

| i | moves[i] | 집은 인형(열, 행) | 바구니 | answer |
|---|---|---|---|---|
| 0 | 1 | 4 (열1, 행3) | [4] | 0 |
| 1 | 5 | 3 (열5, 행1) | [4,3] | 0 |
| 2 | 3 | 1 (열3, 행2) | [4,3,1] | 0 |

| 4 | 1 | 3 (열1, 행4) | [4,3,3]→ 3과 3 연속 → pop → [4] | **4** |
| … | | | 이후 터지는 게 없음 | 최종 **4** |

## 오늘 배운 내용

**입력 값이 무엇을 뜻하는지부터 확인한다.** `moves`의 숫자는 좌표가 아니라 **열 번호**였고, 행은 내가 찾는 값이었다. 문제를 읽을 때 각 입력이 "무엇의 번호인지, 0부터인지 1부터인지"를 먼저 한 줄로 적으면 이런 의문이 코드 전에 풀린다.

**2차원 배열은 `board[행][열]`, 그리고 `board.length`는 행 개수, `board[0].length`는 열 개수다.** 두 가지를 구분해서 쓰는 게 습관이 되어야 직사각형 격자에서도 틀리지 않는다.

## 오답노트

- **틀렸던 지점 1**: `moves[i].length`. **왜**: `moves`가 1차원인데 2차원처럼 썼다. **다음에**: 변수의 타입(`int[]`인지 `int[][]`인지)을 `.length` 쓰기 전에 본다.
- **틀렸던 지점 2**: `board[열][j]`로 행과 열이 뒤바뀜. **왜**: "그 열을 훑는다"는 생각을 `board[열]`로 옮겼는데, `board[x]`는 **x번째 행**이다. **다음에**: 훑는 방향에 따라 **바뀌는 쪽이 행인지 열인지** 먼저 정하고 그 자리에 반복 변수를 둔다.
- **틀렸던 지점 3**: 집은 칸을 `0`으로 바꾸지 않음. **왜**: 값을 읽기만 하면 된다고 생각했다. **다음에**: 문제에서 "빠진다/사라진다/제거한다"는 동사는 코드에서 **상태를 바꾸는 줄**로 옮긴다.
- **틀렸던 지점 4**: 반복 조건에 `board[j].length`. **왜**: `j`가 반복 변수인데 그걸 끝값에 썼다. **다음에**: 끝값은 `j`가 변해도 안 변하는 값인지 확인한다.
- **틀렸던 지점 5**: `answer++`로 한 번에 1씩. **왜**: 문제가 "개수"를 묻는데 "횟수"를 셌다. **다음에**: 무엇이 한 번에 몇 개씩 변하는지(터지면 2개) 센다.
- **좋았던 점**: 코드를 짜기 전에 "`moves`가 왜 좌표 하나뿐이지?"를 스스로 의문으로 던졌다. 바구니(스택) 로직은 처음부터 맞았다.

## 꿀팁

**풀이가 입력을 직접 수정하면, 같은 입력을 재사용하는 테스트가 깨진다.** 이 풀이는 집은 칸을 `0`으로 바꿔서 입력 `board`를 변경한다. 처음 세팅한 테스트에서 `cross` 보드를 두 번 썼더니, 앞의 테스트가 보드를 비워서 뒤의 테스트가 엉뚱한 값이 나왔다. 테스트마다 새 보드를 쓰거나 풀이 안에서 복사본을 만들어 쓴다.

## AI라면 어떻게 풀었을까

이동할 때마다 열을 위에서 아래로 훑는 대신, **시작할 때 각 열을 스택(`Deque`)으로 바꿔 둔다.** 아래 행부터 `push`하면 맨 위 인형이 스택의 `top`에 와서, 크레인이 집는 동작이 그대로 `pop` 한 번이 된다. 빈 열이면 `pop`할 게 없으니 건너뛴다. 바구니도 스택이라 **인형 스택에서 `pop` → 바구니 스택 `peek`와 비교**하는 두 스택 구조다.

```java
public int solutionAlt(int[][] board, int[] moves) {
    List<Deque<Integer>> lanes = new ArrayList<>();
    for (int c = 0; c < board[0].length; c++) {
        lanes.add(new ArrayDeque<>());
    }
    for (int row = board.length - 1; row >= 0; row--) {   // 아래 행부터 push
        for (int col = 0; col < board[row].length; col++) {
            if (board[row][col] != 0) {
                lanes.get(col).push(board[row][col]);
            }
        }
    }

    Deque<Integer> basket = new ArrayDeque<>();
    int count = 0;
    for (int move : moves) {
        Deque<Integer> lane = lanes.get(move - 1);     // 열 번호는 1부터
        if (lane.isEmpty()) {
            continue;                                  // 빈 열: 아무 일도 없음
        }
        int doll = lane.pop();                         // 맨 위 인형 집기
        if (!basket.isEmpty() && basket.peek() == doll) {
            basket.pop();
            count += 2;                                // 두 개가 터짐
        } else {
            basket.push(doll);
        }
    }
    return count;
}
```

트레이드오프: 입력 `board`를 수정하지 않고, 이동마다 열을 훑을 필요 없이 `pop` 한 번으로 끝난다. 대신 처음에 보드를 한 번 전부 읽어 스택으로 옮기는 시간이 들고, 코드가 길어 보인다. 이 문제는 최대 30 x 30, 이동 1,000번이라 어느 쪽이든 충분히 빠르다. 랜덤 20,000건에서 본인 풀이와 출력이 일치했다.
