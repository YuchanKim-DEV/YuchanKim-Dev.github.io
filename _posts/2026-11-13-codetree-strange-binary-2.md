## 문제 설명

어떤 수 N을 2진수로 쓴 뒤 **정확히 한 자리만 바꿔** 만든 문자열 `a`가 주어진다. 가능한 N 중 최댓값을 구한다.

```
1010 → 14   (1110의 두 번째 자리를 바꾸면 1010)
```

## 시행착오

거꾸로 생각하는 문제다. `a`에서 한 자리를 바꾼 것이 N이므로, 바꿀 자리를 골라 N을 가장 크게 만들면 된다.

### 어느 자리를 바꿔야 가장 큰가

- 0을 1로 바꾸면 수가 커진다. 그중에서도 **가장 앞쪽의 0**을 바꿔야 가장 많이 커진다. (높은 자리일수록 값이 크다.)
- 0이 하나도 없으면(`111`) 바꿀 수 있는 것은 1→0뿐이다. 반드시 한 자리는 바꿔야 하니 **가장 낮은 자리**를 바꿔 손해를 최소로 한다. (`111` → `110` = 6)

처음에는 "0이 없으면 그냥 그대로 두는 것"을 생각할 수 있지만, 문제 조건이 "정확히 한 자리를 바꿨다"라서 안 바꿀 수 없다.

## 최종 코드

```java
StringBuilder sb = new StringBuilder();
boolean firstZero = false;
for (int i = 0; i < a.length(); i++) {
    if (a.charAt(i) == '0' && !firstZero) {
        firstZero = true;
        sb.append("1");
    } else {
        sb.append(a.charAt(i));
    }
}

if (!firstZero) {
    sb.setCharAt(sb.length() - 1, '0');
}

int N = Integer.parseInt(sb.toString(), 2);
```

## 추적표: `1010`

| i | a[i] | firstZero | 붙인 값 |
|---|---|---|---|
| 0 | 1 | false | 1 |
| 1 | 0 | false → true | **1** |
| 2 | 1 | true | 1 |
| 3 | 0 | true | 0 |

`1110` → 14.

## 오늘 배운 내용

- 2진수는 **앞자리 한 비트가 뒤쪽 전부를 합한 것보다 크거나 같다.** 그래서 "가능한 한 앞을 바꾸는 쪽"이 그리디로 맞다.
- `Integer.parseInt(문자열, 2)`로 2진 문자열을 바로 10진수로 바꾼다.
- "정확히 한 번 바꿔야 한다"는 조건은 **바꾸지 않는 경우가 없다**는 뜻이다. 모두 1인 경우가 예외가 된다.

## 오답노트

- 이번에는 한 번에 통과했다. 예외(`111`, `000`, 한 자리)를 손으로 돌려 보면 `111`에서만 분기가 필요한 것을 확인할 수 있다.

## AI라면 어떻게 풀었을까

그리디 대신 **그냥 모든 자리를 하나씩 뒤집어 보고 최댓값을 고른다.** 제목이 "자리 수 단위로 완전탐색"인 이유다.

```java
int best = 0;
for (int i = 0; i < a.length(); i++) {
    char[] c = a.toCharArray();
    c[i] = (c[i] == '0') ? '1' : '0';
    best = Math.max(best, Integer.parseInt(new String(c), 2));
}
```

길이가 n이면 후보가 n개뿐이라 충분히 빠르고, `111` 같은 예외 처리도 필요 없다. 내 풀이는 O(n) 그리디지만 예외 분기가 하나 생긴다는 차이가 있다.
