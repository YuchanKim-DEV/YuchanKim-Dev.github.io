[테스트 콘솔]({% post_url 2026-10-26-govtech-korea-voice-gateway-test-console %})은 브라우저 하나가 민원인과 상담원을 동시에 흉내 내는 개발 도구였다. 그런데 팀원이 직접 들어와 써 보려고 하니 문제가 보였다. **누가 무엇을 눌러야 하는지 화면만 보고는 알 수 없었다.** 그래서 두 역할을 실제 앱처럼 따로 만들었다 ([PR #24](https://github.com/GovTech-korea/GovTech-Korea_VoiceGateway/pull/24)).

## 바뀐 것

| 화면 | 모양 | 흐름 |
|---|---|---|
| 상담원 앱 | 남색·파랑 | 로그인 → 대기(대기/자리 비움) → **전화 수신 화면**(받기/거절, 남은 시간 막대) → 통화(통화 시간, 보호 중 안내, 들은 소리, 위험 구간 차단) |
| 민원인 앱 | 흰색·초록 | 말하는 방법 고르기 → 초록 전화 버튼 → 대기 순번·연결 중 → 상담 중(통화 시간, 소리 막대) → 빨간 끊기 |

- MVP의 실제 클라이언트는 **안드로이드 앱 두 개**라서, 테스트 화면도 휴대폰 앱처럼 그렸다
- 넓은 화면에서는 휴대폰 틀 안에 앱을, 옆에 사용 순서를 보여 준다. 휴대폰으로 열면 틀 없이 화면을 꽉 채운다
- 두 역할은 **색으로 바로 구분**된다. 한 화면에 나란히 띄워도 헷갈리지 않는다

기존 통합 콘솔(`/test/console.html`)은 혼자 시험하거나 게이트웨이 상태를 볼 때 쓰도록 그대로 두었다.

## 구조: 화면은 상태만 보고 그린다

세 화면(상담원, 민원인, 통합 콘솔)이 스크립트 하나를 같이 쓴다. 스크립트는 페이지에 있는 칸만 동작시키고, 지금 상태를 `<body data-agent="RINGING">`처럼 속성 하나로 알린다. 무엇을 보여 줄지는 CSS가 정한다.

```css
[data-agent="RINGING"] .view-ring { display: flex; }   /* 전화 수신 화면 */
[data-agent="IN_CALL"] .view-call { display: flex; }   /* 통화 화면 */
```

덕분에 화면을 통째로 갈아엎어도 통화 로직(WebSocket, 마이크, 재생)은 한 줄도 바꾸지 않았다.

### 잡은 함정 하나

통화 화면의 소리 그래프 막대가 **검은색**으로 나왔다. 그래프 색은 CSS 변수에서 읽는데, 앱마다 색이 달라서 변수를 문서 맨 위가 아니라 **앱 틀 요소**에 정의해 두었기 때문이다. 문서 루트에서 읽으면 값이 비어서 기본색(검정)이 된다. 캔버스 요소 기준으로 읽도록 바꿨다 (`getComputedStyle(canvas)`).

## 팀원이 밖에서 들어오는 방법: Cloudflare 임시 터널

게이트웨이는 내 Mac에서 돈다. 팀원이 접속하려면 공개 주소가 필요한데, 배포하기 전에 시범으로 써 보기에는 **cloudflared 임시 터널**이 가장 간단했다.

```bash
cloudflared tunnel --url http://localhost:8080
# → https://xxxx.trycloudflare.com
```

- Mac이 Cloudflare로 **나가는 연결**을 맺고, 그 연결로 요청이 들어온다. 공유기 포트를 열 필요가 없다
- HTTPS 주소가 나와서 팀원 기기에서도 **마이크가 된다.** 브라우저는 `localhost`나 HTTPS에서만 마이크를 허용한다
- WebSocket도 그대로 통과한다
- 터널을 다시 켜면 주소가 바뀐다. 게이트웨이만 재시작하면 주소는 그대로다

## 테스트

- 자동 테스트 94개 통과. 세 화면 응답, 콘솔을 끈 상태에서 새 화면도 404인지 확인
- headless Chrome에서 상담원 탭과 민원인 탭을 따로 띄워 로그인 → 벨 → 받기 → 통화 → 차단 → 끊기의 상태 전환 확인. 라이트/다크, 넓은 화면/휴대폰 폭으로 화면을 캡처해 직접 확인했다
