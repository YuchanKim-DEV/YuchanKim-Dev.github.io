- 문제 링크: 코드트리 가장 많이 나온 쌍 (Chapter 8 > Lesson 1)
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_가장많이나온쌍.java`
- 난이도: Easy, 20XP (정답률 84%)
- 제한: 2 ≤ N ≤ 10, 1 ≤ M ≤ 100, 1 ≤ a, b ≤ N, a ≠ b

## 문제 설명

1 이상 N 이하의 수로 이루어진 수 쌍 `(a, b)`가 M번 주어진다. **가장 많이 나온 쌍이 몇 번 나왔는지** 구한다. `(a, b)`와 `(b, a)`는 같은 쌍이다. 입력을 저장하는 용도 외에는 **이차원 배열을 쓰지 않고** 풀어야 한다. 쌍마다 횟수를 담는 `N × N` 배열을 만들면 안 된다.

```
3 8
1 2 / 2 1 / 3 1 / 1 3 / 2 3 / 2 3 / 2 1 / 1 2   → 4   ((1,2)가 4번)
```

## 시행착오

이번에는 틀린 곳이 없었다. 접근은 "횟수 배열" 대신 **쌍 하나를 잡고 전체를 다시 훑는 이중 반복**이다.

- 바깥 `x`: 쌍 하나를 고른다.
- 안쪽 `y`: **처음부터 끝까지** 훑으며 `x`와 같은 쌍의 개수를 센다. 자기 자신도 한 번으로 세야 하니 `x + 1`부터가 아니다.
- `count`는 `x`마다 `0`으로 초기화하고, `maxCnt`는 맨 위에서 한 번만 만든다.
- **`(a, b)`와 `(b, a)`는 같은 쌍**이라는 조건은 두 쌍 모두 **(작은 값, 큰 값)** 으로 정리해서 비교하는 것으로 처리했다. 순서 두 가지를 `||`로 풀어쓰는 방법도 있지만, 이쪽이 비교식이 한 줄로 끝난다.

## 최종 코드

```java
int maxCnt = 0;
for (int x = 0; x < arr.length; x++) {
    int comp_min = Math.min(arr[x][0], arr[x][1]);
    int comp_max = Math.max(arr[x][0], arr[x][1]);

    int count = 0;
    for (int y = 0; y < arr.length; y++) {
        int comp_min_x = Math.min(arr[y][0], arr[y][1]);
        int comp_max_y = Math.max(arr[y][0], arr[y][1]);

        if (comp_min == comp_min_x && comp_max == comp_max_y) {
            count++;
        }
    }
    maxCnt = Math.max(maxCnt, count);
}
System.out.print(maxCnt);
```

## 추적표: 예제 1에서 `x = 0` (쌍 `1 2`)

`comp_min = 1`, `comp_max = 2`.

| y | 쌍 | (min, max) | (1, 2)와 같은가 | count |
|---|---|---|---|---|
| 0 | 1 2 | (1, 2) | ✅ | 1 |
| 1 | 2 1 | (1, 2) | ✅ | 2 |
| 2 | 3 1 | (1, 3) | ❌ | 2 |
| 3 | 1 3 | (1, 3) | ❌ | 2 |
| 4 | 2 3 | (2, 3) | ❌ | 2 |
| 5 | 2 3 | (2, 3) | ❌ | 2 |
| 6 | 2 1 | (1, 2) | ✅ | 3 |
| 7 | 1 2 | (1, 2) | ✅ | 4 |

이 쌍의 횟수는 4. 다른 쌍들은 2번씩이라 `maxCnt`는 4.

## 오늘 배운 내용

- **"각각이 몇 번 나왔는지"는 횟수 배열이 아니어도 구할 수 있다.** 하나를 잡고 전체를 다시 훑으며 같은 것을 세는 이중 반복이다. 데이터가 작으면(`M ≤ 100`, 1만 번) 충분히 빠르다.
- **순서가 상관없는 쌍은 (작은 값, 큰 값)으로 정리한 뒤 비교한다.** 오늘 틱택토 문제에서 팀 `{p, q}`를 `(작은, 큰)`으로 기록한 것과 같은 아이디어다.
- 이중 반복에서 안쪽은 **0부터 끝까지** 돈다. `i + 1`부터 도는 건 "서로 다른 두 개를 고르는" 경우뿐이다.
- 개수 변수는 바깥 반복마다 초기화하고, 최댓값 변수는 바깥에서 한 번만 만든다.

## 오답노트

- 이번에는 틀린 곳이 없었다.
- 참고: 입력 저장 배열을 `new int[M][N]`으로 만들었다. 열은 2개면 충분하고, 지금은 `N ≥ 2`라 우연히 문제가 없었다. `new int[M][2]`가 의도에 맞는다.

## AI라면 어떻게 풀었을까

(작은 값, 큰 값)을 숫자 하나로 합쳐서 1차원 배열 하나로 비교한다.

```java
int[] key = new int[m];
for (int i = 0; i < m; i++) {
    key[i] = Math.min(a[i], b[i]) * 100 + Math.max(a[i], b[i]);   // (1,2)와 (2,1) 모두 102
}
int best = 0;
for (int i = 0; i < m; i++) {
    int cnt = 0;
    for (int j = 0; j < m; j++) {
        if (key[i] == key[j]) cnt++;
    }
    best = Math.max(best, cnt);
}
```

정리를 앞에서 한 번만 하면 안쪽 비교가 `key[i] == key[j]` 한 줄로 끝난다. 정렬한 뒤 같은 `key`가 연속한 최대 길이를 세는 방법도 있다.
