## 문제 설명

m×n 배열을 **r×c 모양으로 다시 담는다.** 원래 배열을 왼쪽→오른쪽, 위→아래로 읽은 순서 그대로 채운다. 칸 수가 맞지 않아 바꿀 수 없으면 **원래 배열을 그대로** 반환한다.

```
[[1,2],[3,4]], r=1, c=4  →  [[1,2,3,4]]
[[1,2],[3,4]], r=2, c=4  →  [[1,2],[3,4]]   (4칸을 8칸으로는 못 바꿈)
```

오전에 푼 [Transpose Matrix]({% post_url 2026-10-30-transpose-matrix-lc867 %})에 이어 2차원 인덱스를 연습하려고 골랐다.

## 시행착오

전체 구조(1차원 `temp`에 펼치기 → `r×c`에 다시 채우기)는 처음부터 혼자 정했다. 대신 세부에서 여러 번 막혔다.

### 1차: 결과 배열 크기 `new int[c][r]`

방금 Transpose에서 행·열을 뒤집은 게 그대로 따라왔다. `new int[A][B]`는 A행 B열이고, 이 문제는 문제가 준 `r`행 `c`열을 그대로 쓴다.

### 2차: 출력이 전부 0

```java
mat[i][j] = temp[idx];
```

방향이 반대였다. 빈 `temp`로 `mat`을 덮어썼고, `idx`도 올리지 않았다.

### 3차: 세로로 채움 + 값이 사라짐

`row`를 먼저 올려 세로로 채웠다. 또 줄을 넘길 때 `row = 0`으로 넣은 다음 `row++`를 하지 않아, 다음 값이 같은 칸을 덮어썼다.

### 4차: 못 바꾸는 경우 처리 + 줄 끝마다 한 칸이 빔

못 바꾸는 경우를 "원래 크기의 새 빈 배열을 만들고 아래 루프를 그대로 돈다"로 처리해 범위 초과가 났다. 채우기를 가로로 바꾼 뒤에도 줄 끝마다 한 칸씩 비었다.

```java
if (col != c) {
    ans[row][col] = temp[i];
    col++;
} else {
    col = 0;
    row++;
    ans[row][col] = temp[i];   // 여기서 넣고 col++가 없음
}
```

`else`에서 다음 줄 첫 칸에 넣은 뒤 `col++`가 없어서, 다음 값이 같은 칸을 덮어썼다.

### 5차: 통과

여기서 짜증이 나서 코치(Claude)가 고친 코드를 통째로 줘 버렸다. 원한 건 원인 지적이었는데 정답이 왔다. 최종 채우기 루프는 그 코드 그대로라 **이 부분은 다시 백지로 써 봐야 한다.**

## 최종 코드

```java
public int[][] matrixReshape(int[][] mat, int r, int c) {
    if (mat[0].length * mat.length != r * c) {
        return mat;                              // 못 바꾸면 원래 그대로
    }

    int[] temp = new int[mat[0].length * mat.length];
    int idx = 0;
    for (int i = 0; i < mat.length; i++) {       // 1차원으로 펼치기
        for (int j = 0; j < mat[i].length; j++) {
            temp[idx] = mat[i][j];
            idx++;
        }
    }

    int[][] ans = new int[r][c];
    int row = 0;
    int col = 0;
    for (int i = 0; i < temp.length; i++) {
        ans[row][col] = temp[i];                 // 1. 넣고
        col++;                                   // 2. 옆 칸으로
        if (col == c) {                          // 3. 줄 끝이면 다음 줄 첫 칸
            col = 0;
            row++;
        }
    }
    return ans;
}
```

## 추적표: `[[1,2,3],[4,5,6]], r=3, c=2`

`temp = [1,2,3,4,5,6]`

| i | 넣는 칸 | 넣은 뒤 col | 줄 끝? | 다음 위치 |
|---|---|---|---|---|
| 0 | [0][0] ← 1 | 1 | | [0][1] |
| 1 | [0][1] ← 2 | 2 | 예 | [1][0] |
| 2 | [1][0] ← 3 | 1 | | [1][1] |
| 3 | [1][1] ← 4 | 2 | 예 | [2][0] |
| 4 | [2][0] ← 5 | 1 | | [2][1] |
| 5 | [2][1] ← 6 | 2 | 예 | (끝) |

→ `[[1,2],[3,4],[5,6]]`

## 오늘 배운 내용

**칸을 하나씩 옮기며 채울 때는 "넣기 → 옮기기 → 경계 확인" 순서를 지킨다.** 경계 확인을 먼저 하면, 경계를 넘는 바퀴에서만 "넣고 옮기기"가 빠지기 쉽다. 이번에 줄 끝마다 한 칸씩 빈 이유가 이거였다.

**`new int[A][B]`는 A행 B열이다.** 문제가 행·열을 바꾸라고 할 때만 뒤집는다.

## 오답노트

- **틀렸던 지점 1**: `new int[c][r]`. **왜**: 직전 문제의 "뒤집기"를 습관처럼 가져왔다. **다음에**: 결과 크기는 예시 하나(`r=1, c=4` → 1행 4열)로 확인한다.
- **틀렸던 지점 2**: `mat[i][j] = temp[idx]`. **왜**: 대입 방향(오른쪽 → 왼쪽)을 거꾸로 썼다. **다음에**: `=` 왼쪽이 "채우려는 쪽"인지 본다.
- **틀렸던 지점 3**: `else` 안에서 넣은 뒤 `col++` 누락. **왜**: if/else로 나눠서 두 군데에 "넣기"를 쓰다 보니 한쪽만 빠졌다. **다음에**: 같은 동작이 두 분기에 다 있으면 분기 밖으로 빼서 한 번만 쓴다.

## AI라면 어떻게 풀었을까

`temp`를 따로 만들지 않는다. 원래 배열을 읽은 **"몇 번째 칸(k)"**으로 새 위치를 바로 계산한다.

```java
public int[][] matrixReshapeAlt(int[][] mat, int r, int c) {
    int m = mat.length, n = mat[0].length;
    if (m * n != r * c) {
        return mat;                                  // 못 바꾸면 원래 그대로
    }
    int[][] ans = new int[r][c];
    for (int k = 0; k < m * n; k++) {
        ans[k / c][k % c] = mat[k / n][k % n];       // 읽을 때는 n 기준, 쓸 때는 c 기준
    }
    return ans;
}
```

k번째 칸은 "열 수로 나눈 몫이 행, 나머지가 열"이다. `row`·`col`을 직접 올리고 줄 끝을 확인할 필요가 없어서, 이번에 막힌 부분이 통째로 사라진다. 트레이드오프: `/`와 `%`로 2차원 ↔ 1차원을 바꾸는 공식을 알아야 한다. 이 공식은 격자 BFS에서도 자주 쓰인다. 랜덤 20,000건에서 두 풀이의 결과가 같았다.
