## 문제 설명

마을에 1번부터 n번까지 n명이 산다. 판사가 있다면 이 세 조건을 모두 만족한다.

1. 판사는 **아무도 믿지 않는다.**
2. 판사를 뺀 **모든 사람이 판사를 믿는다.**
3. 1과 2를 만족하는 사람은 정확히 한 명이다.

`trust[i] = [a, b]`는 "a가 b를 믿는다"는 뜻이다. 판사 번호를, 없으면 `-1`을 반환한다.

```
n=3, [[1,3],[2,3]]        → 3
n=3, [[1,3],[2,3],[3,1]]  → -1   (3이 1을 믿음)
n=3, [[1,2],[2,3]]        → -1
```

방금 푼 [Find Center of Star Graph]({% post_url 2026-11-02-find-center-of-star-graph-lc1791 %})와 같은 개수 세기 문제다. 차이는 **방향**이 있다는 점이다.

## 시행착오

### 1차: "가장 많이 믿음 받은 사람"?

처음에는 믿음을 가장 많이 받고, 아무도 안 믿는 사람을 찾으면 된다고 생각했다. 그런데 `n=3, [[1,2],[2,3]]`에서 3은 아무도 안 믿지만 1에게 믿음을 받지 못했다. "가장 많이"가 아니라 **"나를 뺀 모두"**, 즉 정확히 `n - 1`개를 받아야 한다.

### 2차: 개수를 어떻게 세지? → 수도코드

조건은 정리됐지만 사람마다 두 개수를 어떻게 셀지 감이 안 왔다. 처음 보는 패턴이라 흐름을 받았다.

```
받은개수[1..n], 준개수[1..n]
[a, b]마다: 준개수[a]++, 받은개수[b]++
1~n 중 받은개수 == n-1 이고 준개수 == 0 → 그 번호
```

### 3차: 실수 3개

```java
int[] earned = new int[n];             // ① 크기 n
...
earned[trust[i][0]]++;                 // ② 받은 쪽/준 쪽 반대
trustOther[trust[i][1]]++;
...
for (int i = 0; i < earned.length; i++)  // ③ 0번부터
```

1. **크기 `n`**: 사람 번호가 n까지라 `earned[n]`에서 `ArrayIndexOutOfBoundsException`이 났다. `n + 1`로 만든다.
2. **방향 반대**: `[a, b]`에서 a(`[0]`)는 믿은 사람, b(`[1]`)는 믿음 받은 사람이다.
3. **0번 검사**: 없는 0번 사람까지 봤다. 1번부터 돈다.

## 최종 코드

```java
public int findJudge(int n, int[][] trust) {
    int[] earned = new int[n + 1];       // 믿음 받은 개수
    int[] trustOther = new int[n + 1];   // 남을 믿은 개수

    for (int i = 0; i < trust.length; i++) {
        earned[trust[i][1]]++;           // b: 믿음 받음
        trustOther[trust[i][0]]++;       // a: 믿음
    }

    for (int i = 1; i < earned.length; i++) {
        if (earned[i] == n - 1 && trustOther[i] == 0) {
            return i;
        }
    }
    return -1;
}
```

## 추적표: `n=4, [[1,3],[1,4],[2,3],[2,4],[4,3]]`

| 사람 | 받은 개수 | 준 개수 | 판사? (받은 == 3, 준 == 0) |
|---|---|---|---|
| 1 | 0 | 2 | ✗ |
| 2 | 0 | 2 | ✗ |
| 3 | **3** | **0** | **✓** |
| 4 | 2 | 1 | ✗ |

→ 3

## 오늘 배운 내용

- **방향 있는 그래프의 개수 세기 = 진입 차수(in-degree)와 진출 차수(out-degree).** 화살표 `a → b`에서 a는 나가는 개수, b는 들어오는 개수가 1씩 오른다. 판사는 진입 차수 `n-1`, 진출 차수 `0`인 노드다.
- **"가장 많이"와 "정확히 몇 개"는 다르다.** 조건이 "모든 사람"이면 정확한 개수로 바꿔 비교한다.
- **번호가 1~n이면 배열 크기는 `n + 1`, 루프는 1부터 n까지.**

## 오답노트

- **막혔던 지점**: 조건을 "가장 많이 받은 사람"으로 읽었다. **다음에**: "모든", "정확히" 같은 말이 나오면 숫자로 바꿔 적는다(모두 = n-1).
- **실수 1**: 1~n 번호에 `new int[n]`. **다음에**: 번호를 인덱스로 쓰면 크기는 최대 번호 + 1.
- **실수 2**: `[a, b]`의 방향을 반대로 넣었다. **다음에**: 쓰기 전에 `[0]`이 누구고 `[1]`이 누구인지 주석으로 먼저 적는다.

## AI라면 어떻게 풀었을까

흐름은 같다. 배열 2개를 **점수 배열 1개**로 합친다. 믿으면 -1, 믿음 받으면 +1이다.

```java
public int findJudgeAlt(int n, int[][] trust) {
    int[] score = new int[n + 1];
    for (int[] t : trust) {
        score[t[0]]--;                 // 믿은 사람
        score[t[1]]++;                 // 믿음 받은 사람
    }
    for (int i = 1; i <= n; i++) {
        if (score[i] == n - 1) {
            return i;
        }
    }
    return -1;
}
```

판사는 받기만 n-1번 하니까 점수가 정확히 n-1이다. 다른 사람은 남을 한 번이라도 믿으면 최대 n-2라서 n-1이 될 수 없다. 트레이드오프: 메모리를 반으로 줄이지만, 왜 맞는지 한 번 더 생각해야 한다. 본인 풀이(두 개수를 따로)가 조건을 그대로 옮겨서 읽기 쉽다. 랜덤 20,000건(전수 조사 풀이와 비교)에서 결과가 같았다.
