- 문제 링크: 코드트리 수들의 최대 차 (Chapter 8 > Lesson 1)
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_수들의최대차.java`
- 난이도: Medium, 30XP (정답률 62%)
- 제한: 1 ≤ N ≤ 1,000, 0 ≤ K ≤ 10,000, 원소는 1 이상 10,000 이하

## 문제 설명

원소 N개와 값 K가 주어진다. 원소를 골라서 **고른 것들의 최댓값 − 최솟값이 K 이하**가 되도록 할 때, 고를 수 있는 **원소의 최대 개수**를 구한다.

```
5 3
1 / 6 / 4 / 3 / 1   → 4   (1, 1, 3, 4)
```

## 시행착오

**정렬이 핵심 관찰**이다. 오름차순으로 정렬하면 "고른 원소의 최솟값 = `arr[i]`, 최댓값 = `arr[j]`"를 정하는 순간, 그 사이 원소를 **전부 골라도** 차이는 `arr[j] - arr[i]`다. 그러니 `(i, j)` 두 개만 정하면 개수는 `j - i + 1`이다.

처음 코드는 구조는 맞았지만 안쪽 반복문에서 세 군데가 틀렸다.

1. **개수 식의 부호가 거꾸로** — `i - j + 1`로 썼다. `i`번째부터 `j`번째까지의 개수는 `j - i + 1`이다. 0이나 음수가 나왔다.
2. **`break`가 없었다** — `j`를 뒤에서부터 내려오니 처음 조건을 만족하는 `j`가 가장 먼 원소다. 멈추지 않고 계속 내려가며 `temp`를 덮어썼다.
3. **`j`가 `i`보다 작은 범위까지 돌았다** — `j > 0`이라 앞 원소를 봤고, `arr[j] - arr[i]`가 음수라 항상 조건을 통과했다. `j`는 `i` 아래로 내려가면 안 된다.

## 최종 코드

```java
Arrays.sort(arr);

int num = 0;
for (int i = 0; i < arr.length; i++) {
    int temp = 0;
    for (int j = arr.length - 1; j > i; j--) {
        if (arr[j] - arr[i] <= k) {
            temp = j - i + 1;     // i~j 사이 원소를 전부 고른다
            break;                // 뒤에서부터 처음 걸린 j가 가장 멀다
        }
    }
    num = Math.max(temp, num);
}
System.out.print(num);
```

## 추적표: 예제 1 (정렬 후 `1 1 3 4 6`, K = 3)

| i | arr[i] | j (뒤에서부터) | arr[j] − arr[i] | 결과 | temp |
|---|---|---|---|---|---|
| 0 | 1 | 4 | 6 − 1 = 5 | ❌ | |
| 0 | 1 | 3 | 4 − 1 = 3 | ✅ break | **4** |
| 1 | 1 | 4 | 5 | ❌ | |
| 1 | 1 | 3 | 3 | ✅ break | 3 |
| 2 | 3 | 4 | 3 | ✅ break | 3 |
| 3 | 4 | 4 | 2 | ✅ break | 2 |

`i = 0`에서 4개가 최대라 `num = 4`.

## 오늘 배운 내용

- **"뽑아서 최대 − 최소"류 문제는 정렬 후 구간으로 바꾼다.** 정렬하면 고른 원소의 최솟값·최댓값이 구간의 양 끝이 되고, 그 사이는 전부 고르는 게 이득이다.
- 뒤에서부터 내려오다 **처음 조건을 만족하는 곳에서 `break`** 하면 가장 먼 끝을 바로 얻는다. `break`를 안 쓰면 마지막에 만족한 값(더 가까운 곳)이 덮어쓴다.
- 개수는 `끝 − 시작 + 1`이다. 부호와 `+ 1`을 한 번 더 확인한다.
- 범위가 `i`보다 앞으로 넘어가면 음수 차이가 항상 조건을 통과해서 엉뚱한 답이 나온다.

## 오답노트

- 개수 식 `i - j + 1` → `j - i + 1`.
- `break` 누락 → 가장 먼 `j`가 덮어써짐.
- `j > 0` → 앞 원소까지 봐서 음수 차이가 조건 통과.
- **남은 허점(코드트리 테스트는 통과)**: 안쪽 반복문이 `j > i`라서 조건을 만족하는 `j`가 하나도 없으면 `temp`가 0이다. `N = 1`이거나 `K`가 작아 어떤 두 원소도 차가 `K` 이하가 아니면, 정답은 **1**(원소 하나만 골라도 차이는 0)인데 이 코드는 **0**을 출력한다. 예: `N = 1, K = 0, [5]` → 정답 1, 이 코드는 0. 제한 조건(`N ≥ 1`, `K ≥ 0`)상 유효한 입력이라, `j >= i`로 바꾸거나 `temp`를 1로 시작해야 안전하다.

## AI라면 어떻게 풀었을까

안쪽 반복문을 `i`부터 시작해서 "자기 자신 1개"도 후보에 넣는다.

```java
Arrays.sort(arr);
int best = 0;
for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {                  // j = i 포함
        if (arr[j] - arr[i] <= k) best = Math.max(best, j - i + 1);
    }
}
```

`break`를 쓰지 않고 모든 `(i, j)`를 보는 대신, 조건을 만족할 때마다 최댓값을 갱신한다. `N = 1` 같은 경우도 `j = i`에서 1이 나오므로 안전하다. 정렬된 배열에서는 `i`를 늘릴 때 `j`도 앞으로만 움직이므로, 투 포인터로 O(N)에도 풀 수 있다.
