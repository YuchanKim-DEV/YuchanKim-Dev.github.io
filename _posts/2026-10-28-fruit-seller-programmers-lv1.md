## 문제 설명

사과를 m개씩 상자에 담아 판다. 상자 가격은 **(그 상자에서 가장 낮은 점수) × m**이다. m개가 안 되게 남은 사과는 버린다. 얻을 수 있는 최대 이익을 구한다.

```
k = 3, m = 4, [1,2,3,1,2,3,1]               → 8    ([2,2,3,3] 한 상자 = 2 × 4)
k = 4, m = 3, [4,1,2,2,4,4,4,4,1,2,4,2]     → 33
```

## 시행착오

### 1차: 오름차순으로 앞에서부터 담음

```java
Arrays.sort(score);
for (int i = 0; i < score.length; i++) { ... }
```

"m개가 안 되면 안 판다"는 조건은 정확히 이해했다. 놓친 건 **어떤 사과가 남아서 버려지느냐**였다.

```
정렬: [1, 1, 1, 2, 2, 3, 3], m = 4
앞에서부터: [1,1,1,2] → 1 × 4 = 4,  남은 [2,3,3] 버림
뒤에서부터: [2,2,3,3] → 2 × 4 = 8,  남은 [1,1,1] 버림
```

앞에서부터 담으면 나쁜 사과로 상자를 채우고 좋은 사과를 버리게 된다. 그리고 `cnt == m`인 바퀴에서는 상자 계산만 하고 그 바퀴의 사과를 담지 않는 문제도 있었다.

### 2차: 통과

`i`를 뒤에서부터 돌리고, `cnt`가 m이 되는 바로 그 바퀴에서 상자를 계산하도록 고쳐 통과했다.

## 최종 코드

```java
public int solution(int k, int m, int[] score) {
    Arrays.sort(score);

    int answer = 0;
    int cnt = 0;
    int minNum = score[score.length - 1];
    for (int i = score.length - 1; i >= 0; i--) {     // 좋은 사과부터
        if (score[i] <= k && cnt < m) {
            cnt++;
            minNum = Math.min(score[i], minNum);
            if (cnt == m) {                            // 상자가 꽉 찬 바로 그때
                answer += m * minNum;
                cnt = 0;
            }
        } else {
            minNum = Math.min(score[i], minNum);
            cnt++;
        }
    }
    return answer;
}
```

`minNum`을 상자마다 초기화하지 않아도 맞는 이유가 있다. 뒤에서부터 읽으면 점수가 줄어들기만 해서, 새 상자의 최솟값은 항상 그 상자 안에서 나온다. `else` 분기는 실제로 실행되지 않는다(`score[i]`는 항상 k 이하, `cnt`는 m이 되자마자 0으로 돌아감).

## 오늘 배운 내용

**무언가를 버려야 하는 문제는 "무엇을 버릴지"부터 정한다.** 남는 사과는 버려지니까 가장 나쁜 사과가 남게 해야 한다. 그러려면 좋은 사과부터 담는다. 오늘 아침 [예산]({% post_url 2026-10-28-budget-programmers-lv1 %})은 "싼 것부터"였고, 이번은 "좋은 것부터"였다. 정렬 방향은 무엇을 남길지에 따라 정해진다.

## 오답노트

- **틀렸던 지점**: 오름차순 정렬 후 `i = 0`부터 담음. **왜**: 예산 문제처럼 앞에서부터 도는 게 익숙했다. 그래서 어떤 사과가 버려지는지 확인하지 않았다. **다음에**: 루프를 쓰기 전에 "다 돌고 나서 남는 건 어느 쪽인가?"를 예시 하나로 확인한다.

## AI라면 어떻게 풀었을까

오름차순으로 정렬하고 뒤에서부터 m개씩 끊는다. 그러면 각 상자의 최저 점수는 **그 상자의 맨 앞 칸**에 있다. `cnt`와 `minNum` 없이 `i`를 m씩 건너뛰면서 그 칸만 읽으면 된다.

```java
public int solutionAlt(int k, int m, int[] score) {
    Arrays.sort(score);                                  // 오름차순
    int answer = 0;
    for (int i = score.length - m; i >= 0; i -= m) {     // 뒤에서 m개씩 끊은 상자의 맨 앞 칸
        answer += score[i] * m;                          // 그 칸이 상자의 최저 점수
    }
    return answer;
}
```

트레이드오프는 없다. 상자 수만큼만 돌아서 더 빠르고, 남는 사과는 `i >= 0` 조건으로 자연히 빠진다. 랜덤 20,000건에서 두 풀이의 결과가 같았다.
