- 문제 링크: 코드트리 팀으로 하는 틱택토 2 (Chapter 8 > Lesson 1)
- 파일 경로: `src/main/java/coding_test/완전탐색/CT_팀으로하는틱택토2.java`
- 난이도: Medium, 50XP (정답률 51%, 평균 86분)
- 제한: 3 × 3 판, 각 칸은 1~9의 정수

## 문제 설명

게임이 끝난 3 × 3 판이 주어진다. 줄은 **가로 3 + 세로 3 + 대각선 2 = 8개**다. 어떤 줄의 세 칸이 모두 `p` 또는 `q`이고 `p`, `q`가 각각 한 번 이상 나오면 팀 `{p, q}`가 이긴 것이다. 번호가 한 종류뿐인 줄(`1-1-1`)은 개인이 이긴 것이라 세지 않는다. **이길 수 있었던 서로 다른 팀의 개수**를 구한다. `{p, q}`와 `{q, p}`는 같은 팀이고, 같은 팀이 여러 줄에서 이겨도 한 번만 센다.

```
124 / 332 / 561   → 2   (대각선 1-3-1 → {1, 3}, 가로 3-3-2 → {2, 3})
189 / 167 / 167   → 2   (세로 8-6-6 → {6, 8}, 세로 9-7-7 → {7, 9})
```

## 시행착오

입력이 `124`처럼 **공백 없는 세 자리 수**라 읽는 것부터 막혔다.

- 처음에는 `charAt(j)`를 그대로 `int`에 넣었다. `'1'`이 숫자 1이 아니라 **문자 코드 49**로 저장된다. 숫자로 바꾸려면 `c - '0'`이 필요하다.
- 안쪽 반복문에서 `j++` 대신 `i++`를 썼다 → 무한 반복.
- 결국 줄을 `int`로 읽고 `% 10`, `/ 10`으로 뒤에서부터 자릿수를 떼는 방식으로 바꿨다. 이때 `input % 10`처럼 배열 전체에 연산을 걸어 컴파일 에러(`input[i]`여야 함).

판을 읽은 뒤의 틀린 곳은 논리였다.

1. **세로 3줄을 빠뜨렸다.** 가로와 대각선만 봐서 예제 2가 0으로 나왔다.
2. **줄의 개수를 셌다.** `teamWon++`는 "팀이 이긴 줄의 수"다. 문제는 "서로 다른 팀의 수"다. `121 / 212 / 121`처럼 같은 팀 `{1, 2}`가 6줄에서 이기면 정답은 1인데 6이 나온다.
3. **`int p, q = 0;`**: `q`만 0으로 초기화되고 `p`는 값이 없어 컴파일 에러가 났다. 4군데 복붙된 곳을 모두 고쳐야 했다.

## 최종 코드 (줄 하나를 처리하는 부분)

```java
boolean[][] won = new boolean[10][10];   // 맨 위에서 한 번만

// 줄 하나(player[번호] = 등장 횟수)를 센 뒤
int playerCount = 0;
for (int k = 0; k < player.length; k++) {
    if (player[k] > 0) playerCount++;
}
if (playerCount == 2) {
    int p = 0, q = 0;
    for (int k = 0; k < player.length; k++) {
        if (player[k] > 0) {
            if (p == 0) p = k;     // 작은 번호가 먼저 걸린다
            else q = k;
        }
    }
    won[p][q] = true;              // (작은, 큰)으로 기록 → {p,q}와 {q,p}가 같은 칸
}
// 마지막에 won에서 true인 칸의 수를 센다
```

이 블록을 가로, 세로, 대각선 두 곳(총 4군데)에 같은 모양으로 넣었다.

## 추적표: 예제 2 `189 / 167 / 167`

| 줄 | 세 칸 | 번호 종류 | 결과 |
|---|---|---|---|
| 가로 1 | 1-8-9 | 3 | 없음 |
| 가로 2 | 1-6-7 | 3 | 없음 |
| 가로 3 | 1-6-7 | 3 | 없음 |
| 세로 1 | 1-1-1 | 1 | 개인 |
| 세로 2 | 8-6-6 | 2 | `won[6][8]` |
| 세로 3 | 9-7-7 | 2 | `won[7][9]` |
| 대각선 | 1-6-7 | 3 | 없음 |
| 반대 대각선 | 9-6-1 | 3 | 없음 |

`true`인 칸은 `won[6][8]`, `won[7][9]` 두 개 → 답 2.

## 오늘 배운 내용

- **"서로 다른 것의 개수"는 개수를 올리지 말고 기록한다.** 이미 센 것을 `boolean` 배열(방문표)로 기억해 두면 중복이 자동으로 한 번만 센다.
- **순서 없는 쌍**은 `(작은 값, 큰 값)`으로 통일해 기록한다. 그러면 `{p, q}`와 `{q, p}`가 같은 칸이다.
- `char`를 숫자로: `c - '0'`. 그냥 `int`에 넣으면 문자 코드가 들어간다.
- `int p, q = 0;`은 `p`를 초기화하지 않는다. 변수마다 `= 0`을 붙여야 한다.
- 같은 코드가 4군데 복붙되면 고칠 때 4군데를 다 고쳐야 한다. 반복되는 일은 **메서드**로 묶는다.

## 오답노트

- `charAt` 값을 그대로 `int`에 저장 → 문자 코드(49 등)가 들어감.
- 안쪽 반복문 변수를 `i++`로 씀 → 무한 반복.
- 세로 줄 누락 → 8개 줄 중 3개를 안 봄.
- `teamWon++`로 줄 수를 셈 → 같은 팀이 여러 줄에서 이기면 중복.
- `int p, q = 0;` → `p` 미초기화 컴파일 에러.

## AI라면 어떻게 풀었을까

줄 하나를 처리하는 일을 메서드 하나로 묶는다. 번호 종류를 세는 배열도 필요 없다. 세 값의 최솟값 `lo`와 최댓값 `hi`만 보면 된다. 세 값이 모두 `lo` 또는 `hi`이고 `lo != hi`이면 정확히 두 종류다.

```java
static void check(int a, int b, int c, boolean[][] won) {
    int lo = Math.min(a, Math.min(b, c));
    int hi = Math.max(a, Math.max(b, c));
    if (lo != hi
            && (a == lo || a == hi) && (b == lo || b == hi) && (c == lo || c == hi)) {
        won[lo][hi] = true;
    }
}

for (int i = 0; i < 3; i++) {
    check(g[i][0], g[i][1], g[i][2], won);   // 가로
    check(g[0][i], g[1][i], g[2][i], won);   // 세로
}
check(g[0][0], g[1][1], g[2][2], won);       // 대각선
check(g[0][2], g[1][1], g[2][0], won);       // 반대 대각선
```

4군데 복붙되던 "종류 세기 + `p`, `q` 찾기"가 `check` 한 번으로 줄고, 고칠 곳도 한 군데뿐이다. 핵심은 그대로 **`(작은 값, 큰 값)`으로 기록해 같은 팀을 한 번만 센다**는 점이다.
