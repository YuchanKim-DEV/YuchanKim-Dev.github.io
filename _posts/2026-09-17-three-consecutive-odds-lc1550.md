## 문제 설명

정수 배열 `arr`이 주어진다. 홀수가 연속으로 3개 나오는 구간이 있으면 `true`, 없으면 `false`를 반환한다.

```
Input: arr = [1,2,34,3,4,5,7,23,12]
Output: true  // [5,7,23]이 연속된 홀수 3개
```

## 시행착오

앞 문제(485)와 같은 "누적 카운터 + 리셋" 구조를 그대로 가져왔다 — 홀수를 만나면 `count`를 늘리고, 짝수를 만나면 `count`를 0으로 리셋.

처음엔 485처럼 최댓값을 추적하는 변수를 따로 만들어야 하나 고민했는데, 곧 이 문제는 "가장 긴 연속 구간이 몇 개인가"가 아니라 "3에 도달하는 순간이 있는가"만 물어본다는 걸 깨달았다. 그래서 `count`가 3이 되는 순간 바로 `true`를 반환하도록 바꿨다. 이 덕분에 `max` 같은 변수를 아예 만들 필요가 없어졌고, 루프가 끝날 때까지 3에 못 도달하면 그냥 `false`를 반환하면 끝났다.

## 최종 코드

```java
public boolean threeConsecutiveOdds(int[] arr) {
    int count = 0;
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] % 2 == 1) {
            count++;
            if (count == 3) {
                return true;
            }
        } else {
            count = 0;
        }
    }
    return false;
}
```

## 오늘 배운 내용

**"최댓값이 얼마인가"를 묻는 문제와 "조건을 만족하는 순간이 있는가"를 묻는 문제는 설계가 다르다.** 후자는 조건이 충족되는 즉시 반환하면 끝나기 때문에, 최댓값을 추적하는 변수 자체가 필요 없다. 문제를 코드로 옮기기 전에 "이게 최댓값 문제인가, 존재 여부 문제인가"부터 구분하면 불필요한 변수를 하나 줄일 수 있다.

## 오답노트

이번엔 크게 틀린 지점은 없었다. 대신 485에서 짠 구조를 그대로 재사용하려다가, 문제 성격이 다르다는 걸 알아채고 중간에 설계를 바꾼 과정 자체가 기록할 만하다 — 같은 카운터 패턴이라도 "무엇을 반환해야 하는가"에 따라 최댓값 변수가 필요할 수도, 안 필요할 수도 있다.

## AI라면 어떻게 풀었을까

배열 길이가 3 미만이면 애초에 답이 나올 수 없다는 조건을 먼저 걸러내면, 매 인덱스에서 "그 지점부터 3칸이 전부 홀수인가"만 직접 확인하는 것도 가능하다.

```java
for (int i = 0; i + 2 < arr.length; i++) {
    if (arr[i] % 2 == 1 && arr[i + 1] % 2 == 1 && arr[i + 2] % 2 == 1) {
        return true;
    }
}
return false;
```

지금 짠 카운터 방식이 O(n)에 한 번만 훑는 더 효율적인 방법이고, 이 "윈도우 3칸을 직접 확인" 방식은 조건이 "3개"로 고정돼 있어서만 성립하는 특수한 풀이다. 다만 코드만 보면 "무엇을 확인하는지"가 카운터 방식보다 더 직관적으로 읽혀서, 처음 문제를 이해할 때 이 형태로 먼저 짚어보는 것도 나쁘지 않다.
