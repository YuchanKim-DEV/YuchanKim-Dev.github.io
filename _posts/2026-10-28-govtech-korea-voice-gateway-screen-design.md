## 1. 역할별 앱 화면 분리

[테스트 콘솔]({% post_url 2026-10-26-govtech-korea-voice-gateway-test-console %})은 브라우저 하나가 민원인과 상담원을 동시에 흉내 내는 개발 도구였다. 그런데 팀원이 직접 들어와 써 보려고 하니 **누가 무엇을 눌러야 하는지 화면만 보고는 알 수 없었다.** 그래서 두 역할을 실제 앱처럼 따로 만들었다.

| 화면 | 흐름 |
|---|---|
| 상담원 앱 | 로그인 → 대기(대기/자리 비움) → **전화 수신 화면**(받기/거절, 남은 시간 막대) → 통화(통화 시간, 보호 중 안내, 들은 소리, 위험 구간 차단) |
| 민원인 앱 | 말하는 방법 고르기 → 초록 전화 버튼 → 대기 순번·연결 중 → 상담 중(통화 시간, 소리 막대) → 빨간 끊기 |

- MVP의 실제 클라이언트가 **안드로이드 앱 두 개**라서 테스트 화면도 휴대폰 앱처럼 그렸다.
- 넓은 화면에서는 휴대폰 틀 안에 앱을 넣고, 옆에 사용 순서를 보여 준다. 휴대폰으로 열면 틀 없이 화면을 꽉 채운다.

### 화면은 상태만 보고 그린다

세 화면이 스크립트 하나를 같이 쓴다. 스크립트는 페이지에 있는 칸만 동작시키고, 지금 상태를 `<body data-agent="RINGING">`처럼 속성 하나로 알린다. 무엇을 보여 줄지는 CSS가 정한다.

```css
[data-agent="RINGING"] .view-ring { display: flex; }   /* 전화 수신 화면 */
[data-agent="IN_CALL"] .view-call { display: flex; }   /* 통화 화면 */
```

이 구조 덕분에 이후 디자인을 여러 번 갈아엎는 동안 통화 로직(WebSocket, 마이크, 재생)은 한 줄도 바꾸지 않았다.

**함정:** 소리 그래프 막대가 **검은색**으로 나왔다. 그래프 색은 CSS 변수에서 읽는데, 앱마다 색이 달라서 변수를 문서 맨 위가 아니라 앱 틀 요소에 정의해 두었다. 문서 루트에서 읽으니 값이 비어 기본색(검정)이 된 것이다. 캔버스 요소 기준으로 읽도록 바꿨다(`getComputedStyle(canvas)`).

### 팀원이 밖에서 들어오는 방법

게이트웨이는 내 Mac에서 돈다. 배포 전 시범용으로는 **cloudflared 임시 터널**이 가장 간단했다.

```bash
cloudflared tunnel --no-autoupdate --protocol http2 --url http://localhost:8080
# → https://xxxx.trycloudflare.com
```

- Mac이 Cloudflare로 **나가는 연결**을 맺는 방식이라 공유기 포트를 열 필요가 없다.
- HTTPS 주소라서 팀원 기기에서도 마이크가 된다. 브라우저는 `localhost`나 HTTPS에서만 마이크를 허용한다.
- 터널을 다시 켜면 주소가 바뀐다.
- 처음에는 기본 프로토콜(QUIC, UDP)로 켰다. 그런데 이 네트워크에서는 30분쯤 지나면 "no recent network activity"로 끊기고 주소까지 사라졌다. `--protocol http2`(TCP)로 바꾼 뒤로는 안정적이다.

## 2. 오디오 파일로 말하기

마이크 대신 녹음 파일을 민원인 목소리로 보내는 기능이다. 같은 욕설 시나리오를 몇 번이든 똑같이 재현할 수 있어서 측정에 꼭 필요하다.

- "오디오 파일 재생"을 골랐을 때만 **파일 올리기** 버튼이 보인다. 파일 창을 취소해도 버튼으로 다시 고를 수 있다.
- 지원 형식(WAV · MP3 · M4A · OGG · FLAC)을 적어 두고, 고른 파일 이름은 20자까지 보여 준다.
- 통화 중에 파일을 바꾸면 화면 표시와 실제로 나가는 소리가 어긋난다. 그래서 통화 중에는 버튼을 잠근다. 빠르게 여러 번 고르면 마지막 파일만 쓰고, 못 읽는 파일을 고르면 이전 파일을 유지한다.

같은 합성 음성을 실제 STT(nemotron)에 두 번 넣었더니 한 번은 "개새끼야", 한 번은 "개색기야"로 받아 적었다. 키워드 목록에 변형을 넣어 두어 둘 다 잡혔지만, STT 결과가 매번 조금씩 다르다는 걸 보여 준 사례다.

## 3. MOMIN 브랜드 입히기

팀이 만든 워드마크(태극 O), 앱 아이콘, 해태 캐릭터를 실제 이미지로 넣었다.

- **색은 이미지에서 직접 뽑았다.** 픽셀을 세어 보니 남색 `#001E4E`과 빨강 `#FC1E2A`이 대부분이었다. 이를 기준으로 남색·빨강·흰색만 쓰고 기존 초록·파랑은 걷어냈다.
- **해태는 화면마다 역할이 있다.**
  - 시작 화면: "공공 서비스를 지키는 수호자"
  - 민원인 앱: 상담 센터의 얼굴
  - 상담원 앱 대기 화면: "해태가 함께 지키고 있어요"
- 통화 받기(초록)와 끊기(빨강)는 전화 앱 관례대로 남겼다. 브랜드보다 "바로 알아보는 것"이 먼저다.

**함정 두 개**
- **워드마크 원본은 흰 배경이다.** 연회색 바탕 위에 올리면 흰 사각형이 드러난다. 라이트 모드에서는 `mix-blend-mode: multiply`로 흰색을 바탕에 섞고, 다크 모드에서는 일부러 흰 배지 위에 올렸다.
- **캐릭터를 원보다 크게 키우면** 아래쪽 제목을 덮는다. 원 위쪽으로 튀어나오게 위치를 바꿨다.

## 4. 시작 화면 문구: 슬로건보다 이름 하나

브랜드를 입히면서 시작 화면에 캐치프레이즈("상담사를 지키고, 국민의 시간을 지킨다."), 설명 문단, "보호·공정·효율" 표시를 넣었다. 써 놓고 보니 말이 많았다.

1. 먼저 하는 일을 그대로 적은 한 줄로 줄였다. "AI가 욕설·위험을 감지해 상담사를 보호합니다"
2. 결국 이 한 줄도 빼고 서비스 이름 **MOMIN**만 남겼다. 무엇을 하는지는 바로 아래 역할 카드와 화면 자체가 보여 준다.

테스트 화면은 홍보물이 아니라 도구다. 읽는 사람이 바로 다음 행동(상담원 / 민원인 고르기)으로 넘어가는 편이 낫다.

## 5. 시작 화면 배치와 통합 콘솔

제목을 한 단어로 줄이자 새 문제가 보였다. 제목은 왼쪽 끝, 해태는 오른쪽 끝에 붙어 가운데가 텅 비었다. 원인은 `grid-template-columns: 1.15fr 0.85fr`이었다. 긴 문장이 있을 때는 왼쪽 칸이 채워졌지만, 다섯 글자만 남으니 칸만 넓고 내용은 없었다. 칸 너비를 내용에 맞추고(`auto auto`) 묶음 전체를 가운데로 보냈다. 한 단어 제목은 크게 써야 무게가 맞아서 글자도 키웠다.

```css
.hero { grid-template-columns: auto auto; justify-content: center; gap: clamp(28px, 7vw, 88px); }
.hero h1 { font-size: clamp(64px, 11vw, 120px); }
```

통합 콘솔은 맨 아래 작은 글자 링크 하나뿐이라 팀원들이 찾지 못했다. 그래서 입구를 두 곳에 만들었다.
- 헤더 오른쪽 "통합 콘솔" 버튼
- 역할 카드 아래의 점선 카드 (개발·시연용임을 표시)

콘솔만 예전 회색 관리자 화면이라 브랜드를 입히고 다시 배치했다. 순서는 상담원|민원인 → 타임라인 → 게이트웨이|STT 서버 → STT로 보낸 음성이다.
- **STT 서버:** "연결 주소: ws://…" 한 줄 대신 서버·경로·언어·전체 주소로 나눠 보여 준다.
- **녹음:** 표 사이에 끼어 있던 재생기를 별도 섹션의 카드로 뺐다.

**리뷰에서 잡은 것**
- **적용 결과가 1초 만에 사라졌다.** 잘못된 주소를 넣어 400이 나도, 1초마다 도는 상태 갱신이 안내문을 바로 덮어썼다. 결과를 8초 동안 남긴다.
- **역할 색이 엇갈렸다.** 패널에서는 상담원이 남색인데, 타임라인에서는 상담원 줄이 빨강이었다. 타임라인 기준으로 통일했다.

## 6. 카드 제목은 역할 이름으로

시작 화면 카드 제목이 "전화를 받는 사람", "전화를 거는 사람"이었다. 서비스 안에서는 모두 **상담원**, **민원인**이라고 부르는데 첫 화면만 다른 말을 쓰고 있었다. 그래서 제목을 역할 이름으로 바꿨다. 바로 위에 있던 "상담원 앱"·"민원인 앱" 작은 글씨는 제목과 겹쳐서 뺐다.

## 7. 100vh와 100dvh: 모바일 아래 여백

휴대폰에서 앱 화면 아래에 빈 여백이 생기고, 끝까지 내려도 페이지가 조금 더 스크롤됐다. 원인은 높이 단위가 섞인 것이었다.

| 요소 | 높이 | 뜻 |
|---|---|---|
| 앱 틀 `.device` | `100dvh` | 지금 보이는 높이 (주소창 제외) |
| 바깥 `body`, `.stage` | `min-height: 100vh` | 주소창이 **숨었을 때**의 큰 높이 |

모바일 브라우저의 `100vh`는 주소창이 접힌 상태를 기준으로 한다. 그래서 주소창이 보이는 동안에는 바깥 페이지가 주소창 높이만큼 더 길어졌다. 좁은 화면에서는 바깥 페이지를 보이는 높이에 고정하고, 스크롤은 앱 안에서만 일어나게 했다.

```css
@media (max-width: 820px) {
  html:has(.stage), body:has(.stage) { height: 100%; overflow: hidden; overscroll-behavior: none; }
  .stage { height: 100vh; height: 100dvh; }   /* dvh를 모르는 브라우저는 vh */
  .screen { overscroll-behavior: contain; }   /* 안쪽 스크롤이 끝나도 바깥으로 넘기지 않음 */
}
```

`:has(.stage)`로 앱 화면이 있는 페이지에만 적용했다. 시작 화면과 통합 콘솔은 원래 긴 페이지라 평소처럼 스크롤된다.

## 8. 민원인 앱도 같은 색으로, 스크롤 없이 한 화면에

상담원 앱은 남색 바탕에 빨강 포인트인데 민원인 앱만 흰 바탕이었다. 같은 서비스의 두 앱이 따로 만든 것처럼 보여서, 민원인 앱의 색 변수를 상담원 앱과 같은 값으로 맞췄다.

스크롤 문제는 직접 재 보니 원인이 분명했다. 민원인 화면 내용은 647px인데 휴대폰에서 쓸 수 있는 높이는 552~616px이었다. 게다가 대기 상태에서도 **보이지 않는 칸이 자리를 차지**하고 있었다.

- 통화 중에만 움직이는 소리 막대: `visibility: hidden`이라 안 보이지만 44px를 그대로 차지했다.
- 비어 있는 통화 시간·안내 문구: `min-height: 22px`만큼 자리를 잡고 있었다.

`visibility: hidden`은 `display: none`으로 바꾸고, 빈 문구는 `:empty`일 때 숨겼다. 해태와 소리 그래프는 화면 높이에 따라 줄어들게 했다.

```css
.app-citizen .call-sub:empty, .app-citizen .call-timer:empty { display: none; }
.app-citizen .avatar { width: clamp(96px, 20dvh, 150px); height: clamp(96px, 20dvh, 150px); }
```

이제 360×600과 390×664 크기에서 대기·통화 중·파일 선택 화면 모두 스크롤이 없다.
