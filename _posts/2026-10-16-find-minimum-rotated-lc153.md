## 문제 설명

오름차순으로 정렬된 서로 다른 원소의 배열을 1~n번 회전시킨 배열이 주어진다. 이 배열의 **최솟값을 반환**한다. 반드시 `O(log n)`이어야 한다.

```
nums = [3,4,5,1,2]         → 1
nums = [4,5,6,7,0,1,2]     → 0
nums = [11,13,15,17]       → 11   (회전했는데 제자리로 돌아온 경우)
```

## 시행착오

이진 탐색 3단계 응용(회전 배열)의 첫 문제이자 **처음 보는 패턴**이었다. 새 패턴이라 규칙을 받는 방식으로 진행했고, 그 전에 문제 자체에서 두 번 헷갈렸다.

### 0차: 문제를 잘못 이해함

1. **"전부 오름차순이 될 때까지 mid를 찾아가면서 배열 순서를 바꿔라"로 읽었다.** 아니다. 배열은 하나도 안 바꾸고 **최솟값이 있는 쪽을 반씩 줄여 가며 찾기만** 한다.
2. 이어서 "문제에는 최소값을 찾으라는 말이 하나도 없는데?"라고 했다. 파일의 Javadoc 18번째 줄(`return the minimum element of this array`)과 51번째 줄(`배열의 최솟값을 반환하라`)에 있었고, 링크 URL(`find-minimum-in-rotated-sorted-array`)과 제목에도 있었다. 설명 블록 끝부분이라 지나치기 쉬운 위치였다. 크레인 인형뽑기에서 배운 대로 **입력과 출력이 무엇인지** 먼저 확인하는 습관이 여기서도 필요했다.

### 1차: 규칙 만들기 (가운데와 맨 오른쪽 비교)

최솟값은 **숫자가 갑자기 작아지는 자리**(`7 → 0`)에 있다. 이 자리가 가운데보다 왼쪽인지 오른쪽인지만 알면 반을 버릴 수 있다.

| 배열 | 가운데 | 맨 오른쪽 | 비교 | 최솟값은? |
|---|---|---|---|---|
| `[4,5,6,7,0,1,2]` | 7 | 2 | 7 > 2 | 가운데보다 **오른쪽** (그 사이에 떨어지는 자리가 있다) |
| `[5,1,2,3,4]` | 2 | 4 | 2 < 4 | 가운데 ~ 오른쪽 끝은 **계속 오름차순** → 가운데이거나 **왼쪽** |

"가운데에서 오른쪽 끝까지 계속 오름차순이면 그 사이에 떨어지는 자리가 없다"를 스스로 말로 풀어 설명했고, 거기서 규칙이 나왔다.

- `nums[mid] > nums[right]` → 최솟값은 mid 오른쪽 → `left = mid + 1` (mid는 버림)
- `nums[mid] < nums[right]` → 최솟값은 mid이거나 왼쪽 → `right = mid` (mid는 후보로 남김)

### 2차: 코드 옮기기

규칙을 코드로 옮기는 건 혼자 했고, 9개 테스트가 한 번에 통과했다. 반복 조건, 범위(`right = nums.length - 1`), 반환까지 맞았다.

## 최종 코드

```java
public int findMin(int[] nums) {
    int left = 0;
    int right = nums.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) {
            left = mid + 1;                  // 떨어지는 자리가 mid 오른쪽
        } else if (nums[mid] < nums[right]) {
            right = mid;                     // mid ~ right 는 오름차순
        } else {
            return nums[mid];                // mid == right (서로 다른 원소라서)
        }
    }
    return nums[left];
}
```

9개 테스트가 통과했고, 랜덤 50,000건(모든 회전)에서 정답과 일치했다.

## 추적표: `[4, 5, 6, 7, 0, 1, 2]`

| 단계 | left | right | mid | nums[mid] vs nums[right] | 이동 |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 > 2 | `left = 4` |
| 2 | 4 | 6 | 5 | 1 < 2 | `right = 5` |
| 3 | 4 | 5 | 4 | 0 < 1 | `right = 4` |
| 4 | 4 | 4 | 4 | 0 == 0 | **0 반환** |

## 오늘 배운 내용

**회전된 정렬 배열은 "가운데와 맨 오른쪽(또는 맨 왼쪽)을 비교하면 어느 쪽 반이 정렬 상태인지 알 수 있다"는 성질로 반을 버린다.** 정렬 상태인 쪽에는 "떨어지는 자리"가 없으니, 최솟값(떨어진 직후의 값)은 반대쪽에 있다. 비교하는 대상을 `right`로 고정하면 규칙이 두 줄로 끝난다.

**이진 탐색은 "정렬된 배열에서 값 찾기"만이 아니라 "한쪽을 버릴 근거가 있으면" 쓸 수 있다.** 이 문제의 근거는 정렬 여부가 아니라 `nums[mid]`와 `nums[right]`의 대소 관계였다.

## 오답노트

- **틀렸던 지점 1**: "배열 순서를 바꿔라"로 읽음. **왜**: "정렬된 배열을 회전시켰다"는 문장에서 "정렬한다"를 먼저 떠올렸다. **다음에**: 문제의 마지막 문장(`return ...`)에서 **무엇을 반환하는지**부터 확인한다.
- **틀렸던 지점 2**: 최솟값을 찾으라는 말이 없다고 착각. **왜**: 긴 설명 블록의 중간 문장이라 지나쳤다. **다음에**: 문제 제목과 링크 URL에도 핵심 동사가 들어 있으니 같이 본다.
- **좋았던 점**: `[5,1,2,3,4]`에서 "계속 오름차순이지"라고 스스로 설명하며 규칙을 도출했다. 그리고 규칙을 코드로 옮길 때 한 줄도 막힘이 없었다.
- **참고**: 처음 보는 패턴이라 규칙(`nums[mid]`와 `nums[right]` 비교)은 제공받았다. 다음 회전 배열 문제(LC33)에서 같은 성질을 다시 써서 정착시킨다.

## AI라면 어떻게 풀었을까

같은 "`mid`와 `right` 비교" 규칙을 **LC35, 입국심사 대안과 같은 반열린 틀**(`left < right`)로 쓴다. 이 틀은 `left`와 `right`가 항상 한 점으로 모여서 끝나므로, 같은 값일 때 따로 반환하는 `else` 분기가 필요 없고 마지막에 `nums[left]` 하나만 돌려주면 된다.

```java
public int findMinAlt(int[] nums) {
    int left = 0;
    int right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) {
            left = mid + 1;                 // 떨어지는 자리가 mid 오른쪽 → mid는 버림
        } else {
            right = mid;                    // mid ~ right 오름차순 → mid는 후보로 남김
        }
    }
    return nums[left];                      // left == right: 최솟값의 위치
}
```

트레이드오프: 분기가 두 개로 줄고 `left <= right`와 `right = mid`가 섞였을 때 생길 수 있는 무한 루프 위험이 없다. 서로 다른 원소 조건에서 `nums[mid] == nums[right]`는 `mid == right`일 때뿐이라 `else`에 자연스럽게 들어간다. 대신 "한 점으로 모일 때까지"라는 틀을 믿어야 해서 처음엔 `return` 위치가 낯설다. 랜덤 50,000건에서 본인 풀이와 출력이 일치했다.
