## 문제 설명

대기 큐에서 프로세스를 하나 꺼낸다. 큐에 남은 것 중 **더 높은 우선순위**가 있으면 방금 꺼낸 것을 다시 큐 맨 뒤에 넣고, 없으면 실행한다(실행한 프로세스는 다시 넣지 않는다). `location`번 프로세스가 **몇 번째로 실행**되는지 구한다.

```
priorities = [2,1,3,2], location = 2   → 1
priorities = [1,1,9,1,1,1], location = 0 → 5
```

## 시행착오

LC2073, LC1700에서 배운 "**큐에는 변하지 않는 식별자(인덱스)를 넣고, 상태는 배열에서 읽는다**"를 그대로 적용해서 큐에 인덱스를 넣는 것까지는 혼자 했다. 막힌 건 새로운 부분, **"남은 것 중 더 높은 우선순위가 있는가"**를 확인하는 방법이었다.

### 1차: 큐 시작 인덱스 오류 → 무한 루프

```java
for (int i = 1; i < priorities.length; i++) {   // 0번이 빠짐
    queue.offer(i);
}
...
for (int i = 0; i < queue.size(); i++) {
    if (priorities[maxIdx] < priorities[i]) {
        while (queue.peek() != i) { ... }        // i=0이면 큐에 0이 없어서 영원히 돔
    }
}
```

큐에 0번이 없는데 반복문은 `i = 0`부터 시작해서, "0이 맨 앞에 올 때까지 돌린다"는 반복이 끝나지 않았다.

### 2차: 한 번만 훑음 (구조 오류)

0을 넣어서 무한 루프는 없앴지만 8개 중 하나만 틀렸고, 랜덤 입력 2,000개 중 약 절반이 틀렸다. **스스로 원인을 찾았다.** "처음 한 번만 정렬하고 다음은 안 한다."

규칙은 "프로세스를 **꺼낼 때마다**, 큐에 남은 것 중 더 높은 게 있는지 확인"인데, 코드는 큐를 **한 번만** 훑었다. 프로세스를 실행할 때마다 "남은 것 중 가장 높은 우선순위"가 바뀐다는 걸 코드에 반영하지 못했다.

### 3차: "실행한다"가 코드로 무엇인지 헷갈림

"더 높은 게 있으면 다시 넣는다"는 알았는데 **"없으면 실행한다"**가 코드로 무엇인지 몰랐다. 답은 "**다시 넣지 않는다 + 실행 순번을 1 올린다**"였다. 표로 `[2,1,3,2]`를 따라가며 설명을 듣고서야 이해했다. 이어서 25분이 지나 수도코드를 받았다. "남은 것 중 최댓값 확인"은 처음 보는 패턴이라 정상 루트였다.

## 최종 코드

```java
public int solution(int[] priorities, int location) {
    Queue<Integer> queue = new ArrayDeque<>();

    for (int i = 0; i < priorities.length; i++) {
        queue.offer(i);                          // 큐에는 인덱스
    }

    int startNum = 0;                            // 실행한 횟수
    while (!queue.isEmpty()) {
        int pollNum = queue.poll();
        boolean higher = false;
        for (int idx : queue) {                  // 방금 꺼낸 것은 큐에 없음 → 남은 것만 본다
            if (priorities[idx] > priorities[pollNum]) {
                higher = true;
            }
        }

        if (higher) {
            queue.offer(pollNum);                // 더 높은 게 있음 → 뒤로
        } else {
            startNum++;                          // 실행 (다시 안 넣음)
            if (pollNum == location) {
                return startNum;
            }
        }
    }
    return startNum;
}
```

8개 테스트가 모두 통과했고, 랜덤 2,000건에서도 정답 시뮬레이션과 틀린 개수가 0이었다.

## 추적표: `[2,1,3,2]`, location = 2

| 꺼낸 것(우선순위) | 큐에 남은 것 중 더 높은 게 있나? | 처리 | 큐 | 실행 순번 |
|---|---|---|---|---|
| 0 (2) | 있음(3) | 다시 넣음 | [1,2,3,0] | 0 |
| 1 (1) | 있음 | 다시 넣음 | [2,3,0,1] | 0 |
| 2 (3) | 없음 | **실행** → location이므로 **1 반환** | | **1** |

## 오늘 배운 내용

**규칙이 "~일 때마다"로 시작하면 그 확인은 반복문 안에서 매번 한다.** 한 번만 정렬하거나 한 번만 훑어서는 안 된다. 프로세스를 실행할 때마다 큐의 상태가 바뀌기 때문이다.

**"실행"은 "꺼냄"의 부분집합이다.** 꺼낸 것 중 다시 넣지 않은 것만 "실행"이고, 문제가 묻는 건 실행 순번이다. 그래서 꺼낸 횟수와 실행한 횟수를 따로 센다.

## 오답노트

- **틀렸던 지점 1**: 큐를 `i = 1`부터 채움. **왜**: 다른 반복문에서 `i = 1`로 시작하던 습관이 섞였다. **다음에**: 큐를 채우는 반복문은 `0`부터 `n-1`까지인지 한 번 읽는다.
- **틀렸던 지점 2**: 큐를 한 번만 훑음. **왜**: 규칙의 "~일 때마다"를 놓쳤다. **다음에**: 문제 규칙을 문장으로 쓰고 "언제마다"가 있으면 그 확인을 `while` 안에 둔다.
- **틀렸던 지점 3**: "실행"을 코드로 옮기지 못함. **왜**: 문장은 이해했지만 "다시 넣지 않는다 + 순번 증가"로 풀어 쓰지 않았다. **다음에**: 문제의 동사(실행한다, 제거한다)를 "큐에서 어떻게 되는가"로 바꿔서 적는다.
- **좋았던 점**: 구조가 틀린 원인을 힌트 없이 스스로 분석했다. 또 큐에 인덱스를 넣는 방식은 LC2073, 1700에서 배운 것을 혼자 적용했다.

## 꿀팁

`for (int idx : queue)`는 **큐를 꺼내지 않고** 내용을 훑는다. 큐의 내용은 그대로이고 앞에서부터 차례로 나온다. 이번처럼 "남은 것 중 조건에 맞는 게 있나?"를 확인할 때 쓴다.

## AI라면 어떻게 풀었을까

큐 안을 매번 처음부터 끝까지 훑는 대신, **우선순위별로 큐에 몇 개 남았는지를 `count[1..9]`에 세어 둔다.** 우선순위가 1~9뿐이라 "더 높은 게 있나?"는 최대 9칸만 보면 된다. 실행될 때만 그 우선순위의 `count`를 줄이고, 큐에는 `{인덱스, 우선순위}` 쌍을 넣어서 `priorities[]`를 다시 찾지 않는다.

```java
public int solutionAlt(int[] priorities, int location) {
    Queue<int[]> queue = new ArrayDeque<>();     // {인덱스, 우선순위}
    int[] count = new int[10];                   // count[k] = 큐에 남은 우선순위 k의 개수
    for (int i = 0; i < priorities.length; i++) {
        queue.offer(new int[] { i, priorities[i] });
        count[priorities[i]]++;
    }

    int order = 0;
    while (!queue.isEmpty()) {
        int[] cur = queue.poll();
        boolean higher = false;
        for (int k = cur[1] + 1; k <= 9; k++) {
            if (count[k] > 0) {
                higher = true;
                break;
            }
        }
        if (higher) {
            queue.offer(cur);                    // 더 높은 게 남아 있음 → 뒤로
        } else {
            order++;                             // 실행
            count[cur[1]]--;
            if (cur[0] == location) {
                return order;
            }
        }
    }
    return order;
}
```

트레이드오프: "더 높은 게 있나?" 확인이 큐 길이만큼 걸리던 것이 최대 9칸으로 줄어서, 큐가 길어져도 한 번의 확인 비용이 일정하다. 대신 `count` 배열을 실행할 때마다 정확히 줄여야 해서 하나라도 빼먹으면 틀리고, 우선순위가 1~9처럼 작은 범위일 때만 쓸 수 있다. 이 문제는 최대 100개라 둘 다 충분히 빠르다. 랜덤 30,000건에서 본인 풀이와 출력이 일치했다.
