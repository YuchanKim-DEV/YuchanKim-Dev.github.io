앱은 아직 만들어지는 중인데, 게이트웨이가 제대로 도는지는 지금 보여 줄 수 있어야 한다. 그래서 게이트웨이가 직접 띄우는 **브라우저 테스트 콘솔**을 만들었다 ([PR #20](https://github.com/GovTech-korea/GovTech-Korea_VoiceGateway/pull/20)). 서버를 켜고 `/test`를 열면, 브라우저 하나가 민원인도 되고 상담원도 된다.

## 화면 구성

| 칸 | 할 수 있는 것 |
|---|---|
| 상담원 | 접속, 대기/자리 비움, 벨 받기·거절(남은 시간 표시), 끊기, **위험 구간 차단**(단축키 M) |
| 민원인 | 마이크 / 테스트 톤 / 오디오 파일로 전화 걸기, 대기 순번 표시 |
| 게이트웨이 | 상담원·대기열·통화 현황, 통화별 STT 전달량, 차단 수, **STT가 받은 음성 듣기** |
| 타임라인 | 최근 10초의 "민원인이 보낸 소리"와 "상담원이 들은 소리", 차단 구간 |

타임라인이 시연의 핵심이다. 두 줄의 간격이 그대로 지연(800ms)이고, 말한 직후 차단을 누르면 상담원 줄에서 그 구간이 비어 있다. 귀로만 듣던 지연과 차단을 눈으로 보여 줄 수 있다.

## 새로 배운 것: 브라우저 마이크를 16kHz PCM으로

브라우저 마이크는 보통 48kHz Float32로 들어온다. 게이트웨이 규격은 16kHz, 16비트 정수, little-endian, 20ms(640바이트) 프레임이다.

- **AudioWorklet**: 오디오 처리를 별도 스레드에서 128샘플 단위로 받는 장치다. 여기서 48k → 16k로 바꾸고(구간 평균으로 높은 소리를 조금 깎은 뒤 선형 보간), 320샘플이 모이면 메인 스레드로 넘긴다
- **바이트 순서를 코드로 못 박기**: `Int16Array`는 기기의 바이트 순서를 따른다. 실제 브라우저는 전부 little-endian이라 동작은 하지만, 규격을 코드로 보장하려고 `DataView.setInt16(i * 2, v, true)`로 썼다
- **재생**: 받은 640바이트를 `AudioBuffer`(16kHz)로 만들어 60ms 여유를 두고 이어 붙인다. 네트워크가 조금 흔들려도 끊기지 않는다

## 사람 대신 Chrome이 시연하게 하기

UI는 단위 테스트로 확인하기 어렵다. 그래서 **headless Chrome을 DevTools 프로토콜(CDP)로 조종하는 시나리오**를 짰다. Chrome의 `--use-fake-device-for-media-stream` 옵션을 켜면 가짜 마이크가 삐 소리를 내 준다.

시나리오는 이렇다. 상담원 접속 → 민원인 전화(테스트 톤) → 벨 → 받기 → 지연 측정 → 차단 → 끊기 → STT 기록 확인 → 마이크로 한 번 더 → 모바일 폭. 확인 항목 20개가 모두 통과했다.

| 확인 | 결과 |
|---|---|
| 들린 시각 - 보낸 시각 | 808~813ms (설정 800ms) |
| 차단 | 40프레임 = 800ms, 그 구간이 상담원 줄에서 빔 |
| STT 기록 WAV | 16kHz, 16비트, 모노. 영교차로 잰 주파수 439Hz (보낸 톤 440Hz) |
| 화면 | 라이트/다크, 2배 해상도, 390px 폭에서 가로 스크롤 없음 |

마지막 줄의 WAV 확인이 마음에 든다. "STT 직전까지 전달된다"를 말로 하지 않고, **STT가 받은 바이트를 꺼내 주파수를 재서** 보낸 소리와 같다는 걸 확인했다.

이 시나리오가 버그 두 개를 잡았다.

- **타임라인 높이가 무한히 커질 수 있었다.** 캔버스의 실제 픽셀 수를 화면 크기 × 해상도 배율로 맞추는데, 높이를 CSS로 고정하지 않았다. 그래서 배율이 2인 화면에서는 매 프레임 높이가 다시 커질 수 있었다. CSS로 180px을 고정했다
- **기록 길이가 처음 본 값에서 멈췄다.** 재생 중인 플레이어가 끊기지 않게 목록이 바뀔 때만 다시 그리도록 했더니, 진행 중이던 통화의 길이가 갱신되지 않았다. 설명 줄만 따로 갱신한다

## 리뷰에서 고친 것

- **마이크가 꺼지지 않는 경우.** 마이크는 권한 확인 때문에 늦게 열린다. 그 사이에 통화가 끝나면 끄는 함수가 아직 없어서, 늦게 열린 마이크가 계속 켜져 있었다. 시작할 때마다 **세대 번호**를 올리고, 늦게 열린 마이크의 번호가 지금과 다르면 바로 닫는다
- **현황 조회가 STT를 기다린다.** 현황 API는 상담 상태 잠금을 쥔 채 통화별 STT 전달량을 읽는데, 그 값이 STT 전송 중에 잡히는 잠금 뒤에 있었다. 실제 STT 엔진이 느리면 1초마다 오는 현황 조회가 모든 상담 처리를 멈춘다. 집계 값을 `volatile`로 바꿔 잠금 없이 읽는다
- **콘솔은 인증이 없다.** `voicegateway.test-console.enabled=false`면 페이지와 현황·기록 API가 모두 404가 되게 했다. 정적 파일도 기본 `static/` 대신 별도 폴더에 두고 같은 설정으로 등록해서, 끄면 파일도 나가지 않는다

## CodeQL이 막은 것

PR을 올리자 CodeQL이 `java/path-injection`(high)으로 머지를 막았다. 기록 파일을 받는 API가 요청 경로의 이름으로 `dir.resolve(name)`을 하고 있었다.

이름은 `[A-Za-z0-9_-]{1,64}-\d{1,18}\.pcm` 정규식으로 검사하고 있어서 실제로 폴더 밖으로 나갈 길은 없었다. 하지만 정적 분석은 "검사했으니 안전하다"를 항상 따라오지 못한다. 더 단단한 방법으로 바꿨다. **요청한 이름으로 경로를 만들지 않고, 폴더의 실제 파일 목록에서 이름이 같은 것을 고른다.** 이렇게 하면 검사에 구멍이 있어도 폴더 밖 파일에는 닿을 수 없다.
